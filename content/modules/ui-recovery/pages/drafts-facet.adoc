= Фасет drafts

Фасет `drafts` сохраняет несохраненные изменения экрана в виде черновика и предлагает восстановить черновик, когда пользователь снова открывает экран. Общее описание см. в разделе xref:ui-recovery:index.adoc#how-it-works[Как это работает].

[[adding-facet]]
== Добавление фасета

Объявите пространство имен дополнения в дескрипторе экрана:

[source,xml,indent=0]
----
include::example$ui-recovery-ex1/src/main/resources/com/company/sample/view/order/order-detail-view.xml[tags=namespace]
----

Затем добавьте элемент `uirec:drafts` в элемент `facets`:

[source,xml,indent=0]
----
include::example$ui-recovery-ex1/src/main/resources/com/company/sample/view/order/order-detail-view.xml[tags=facet]
----

В Jmix Studio фасет можно добавить из раздела *Facets* палитры компонентов.

Фасет работает в любом экране, у которого есть xref:flow-ui:data/data-context.adoc[DataContext], и сохраняет изменения, зарегистрированные в нем. В экране деталей черновик относится к редактируемой записи. В других экранах, например в экране списка с редактируемой таблицей данных, у экрана один черновик.

[[minSaveInterval]]
`minSaveInterval`::
Минимальное время между двумя сохранениями черновика экрана, например `5s` или `1m`. Изменения, сделанные в течение этого времени, сохраняются по окончании интервала. Значение по умолчанию задается свойством xref:ui-recovery:app-properties.adoc#jmix.uirecovery.drafts.default-min-save-interval[jmix.uirecovery.drafts.default-min-save-interval].

[[restoreMode]]
`restoreMode`::
Способ восстановления черновика при открытии экрана: `ASK` или `AUTO`. См. <<restore-modes>>. Значение по умолчанию задается свойством xref:ui-recovery:app-properties.adoc#jmix.uirecovery.drafts.default-restore-mode[jmix.uirecovery.drafts.default-restore-mode].

[[saving-and-deleting]]
== Сохранение и удаление черновиков

Фасет сохраняет черновик после того, как пользователь изменил данные в экране, но не чаще, чем позволяет <<minSaveInterval,minSaveInterval>>. Когда экран отсоединяется, например потому что пользователь закрыл вкладку браузера, фасет сразу сохраняет оставшиеся изменения.

Фасет удаляет черновик, когда:

* Пользователь сохраняет изменения.
* Пользователь закрывает экран и подтверждает, что изменения нужно отменить.

Если сохранить черновик не удалось, ошибка записывается в лог, и экран продолжает работать.

[[saving-typed-values]]
== Сохранение вводимых значений

По умолчанию текстовое поле отправляет значение на сервер, когда поле теряет фокус или пользователь нажимает *Enter*. До этого момента введенное значение отсутствует в модели данных и не может быть сохранено в черновике. Если пользователь вводит длинный текст в одно поле, при сбое весь этот текст может быть потерян.

Чтобы отправлять значение во время ввода, установите для атрибута поля xref:flow-ui:vc/common-attributes.adoc#valueChangeMode[valueChangeMode] значение `LAZY` или `TIMEOUT`:

[source,xml,indent=0]
----
include::example$ui-recovery-ex1/src/main/resources/com/company/sample/view/order/order-detail-view.xml[tags=value-change-mode]
----

В этом примере текстовая область отправляет значение, когда пользователь прекращает ввод на одну секунду. Затем значение сохраняется в следующем черновике. Каждое отправленное значение — это запрос к серверу, поэтому используйте эту настройку для полей, в которые пользователи вводят много текста.

[[restore-modes]]
== Режимы восстановления

Когда экран открывается и для него найден черновик, фасет восстанавливает черновик в соответствии с <<restoreMode,режимом восстановления>>.

[[ask-mode]]
=== ASK

Это режим по умолчанию. Фасет показывает диалог с датой черновика:

image::restore-dialog.png[align="center",width="425"]

* *Restore* переносит изменения из черновика в экран. Изменения не сохраняются в базу данных, пока пользователь не сохранит экран.
* *Discard* удаляет черновик.
* *Not now* закрывает диалог и сохраняет черновик. Диалог будет показан снова, когда пользователь в следующий раз откроет экран.

Если запись была изменена другим пользователем после сохранения черновика, диалог предупреждает, что восстановление черновика перезапишет эти изменения:

image::restore-dialog-version-differs.png[align="center",width="560"]

Предупреждение показывается для сущностей с оптимистичной блокировкой, то есть сущностей с атрибутом версии.

[[auto-mode]]
=== AUTO

Фасет восстанавливает черновик без вопроса и показывает уведомление. Черновик хранится в базе данных, пока пользователь не сохранит экран или не отменит изменения. Если работа снова прервется до этого, черновик останется доступен.

[[restoring-details]]
== Что восстанавливается

Фасет восстанавливает только те атрибуты, которые изменил пользователь. Остальные атрибуты сохраняют текущие значения.

Фасет пропускает части черновика, которые больше нельзя применить, и восстанавливает остальное. Например, он пропускает:

* Атрибут, который был удален из сущности в новой версии приложения.
* Запись, которая была удалена после сохранения черновика.

Если черновик вообще не удается прочитать, фасет удаляет его, и экран открывается без восстановления. Пользователь не получает уведомления. Подробности записываются в лог.

[[custom-restore]]
== Собственная логика восстановления

Чтобы в коде решать, восстанавливать ли черновик и как, задайте делегат восстановления. Фасет вызывает его перед стандартным восстановлением. Делегат получает объект `DraftRestoreContext` с найденным черновиком и экраном. Если делегат вызывает `preventRestore()`, фасет не восстанавливает черновик и не показывает диалог.

[[draft-restored-event]]
== DraftRestoredEvent

Фасет отправляет `DraftRestoredEvent` после восстановления черновика. Событие отправляется в обоих режимах восстановления. В этот момент восстановленные значения уже находятся в экране, поэтому можно обновить UI или проверить данные. Изменения, сделанные в обработчике события, сохраняются в следующем черновике.

Метод события `getDraft()` возвращает восстановленный черновик, а `getRestoredEntities()` — экземпляры сущностей, которые были изменены при восстановлении.

Событие не отправляется, если пользователь отменил черновик или отложил решение, если делегат восстановления запретил восстановление или если из черновика ничего не удалось восстановить.

[[methods]]
== Методы

Интерфейс `DraftsFacet` имеет следующие методы:

* `saveDraftNow()` сохраняет черновик немедленно, не дожидаясь окончания <<minSaveInterval,minSaveInterval>>.
* `deleteDrafts()` удаляет черновик текущего экрана и записи.
* `setMinSaveInterval()` и `setRestoreMode()` изменяют значения <<attributes,атрибутов>>.
* `setRestoreDelegate()` задает <<custom-restore,делегат восстановления>>.
* `addDraftRestoredListener()` добавляет слушатель <<draft-restored-event,DraftRestoredEvent>>.
