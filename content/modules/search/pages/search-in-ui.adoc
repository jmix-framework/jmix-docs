= Использование поиска в UI

[[visual-components]]
== Визуальные компоненты

Дополнение Search предоставляет два UI-компонента: xref:search-field-component.adoc[SearchField] и xref:full-text-filter-component.adoc[FullTextFilter].

[[search-strategies]]
=== Стратегии поиска

Стратегия поиска определяет, как обрабатывается поисковый термин. По сути, она конфигурирует поисковый запрос с определенным запросом.

Компоненты xref:search-field-component.adoc[SearchField] и xref:full-text-filter-component.adoc[FullTextFilter] поддерживают следующие встроенные стратегии поиска:

* `startsWith`
+
NOTE: Эта стратегия *доступна только* когда xref:index-definitions.adoc#extended-search[@ExtendedSearch] включен хотя бы для одного определения индекса.
+
Выполняет поиск на основе префикса, используя предварительно индексированные подполя Edge N-Gram:

** Генерирует все префиксы от xref:search-properties.adoc#jmix.search.minPrefixLength[jmix.search.min-prefix-length] (по умолчанию: `3`) до xref:search-properties.adoc#jmix.search.maxPrefixLength[jmix.search.max-prefix-length] (по умолчанию: `8`).
** Обеспечивает значительно более высокую производительность по сравнению с запросами по шаблону (wildcard).
** Когда введенный термин превышает максимальную длину префикса, выполняется резервный запрос по шаблону, если xref:search-properties.adoc#jmix.search.wildcardPrefixQueryEnabled[jmix.search.wildcard-prefix-query-enabled] = `true` (значение по умолчанию).
+
NOTE: Для терминов короче, чем jmix.search.min-prefix-length, поиск всегда возвращает пустой результат.

* `phrase`
+
Выполняет поиск точной фразы:

** Документы должны содержать все поисковые термины в *точном порядке* в рамках одного поля.
** Эквивалентно традиционному фразовому запросу в поисковых системах.
** Идеально подходит для поиска по именам, названиям или точным формулировкам.

* `anyTermAnyField`
+
Выполняет дизъюнктивное сопоставление терминов по всем полям:

** Возвращаются документы, соответствующие *любому* из введенных терминов в *любом* индексированном поле.
** Термины комбинируются с логикой ИЛИ.
** Стратегия по умолчанию для обратной совместимости.

+
Эта стратегия установлена по умолчанию.

CAUTION: `allTermsAnyField` и `allTermsSingleField` объявлены устаревшими и скрыты из пользовательского интерфейса, но при необходимости могут быть повторно реализованы.

[[custom-search-strategies]]
==== Пользовательские стратегии поиска

Дополнительно вы можете создать пользовательскую стратегию поиска. Создайте Spring бин, который наследуется от одного из платформенных базовых классов:

* `AbstractOpenSearchStrategy` - если используется OpenSearch.
* `AbstractElasticSearchStrategy` - если используется Elasticsearch.

Реализуйте методы `getName()` и `configureRequest(SearchRequestContext)`:

[source,java,indent=0]
----
include::example$/search-ex1/src/main/java/com/company/demo/service/CustomOpenSearchSearchStrategy.java[tags=strategy]
----
<1> The base class is initialized with the platform-specific query configurer (`OpenSearchQueryConfigurer` or `ElasticSearchQueryConfigurer`), available as the `queryConfigurer` field.
<2> `getName()` returns a unique strategy name used to select the strategy.
<3> `configureRequest(SearchRequestContext)` is the method the search engine invokes for the strategy — implement it to build the search request.
<4> Build the query through `queryConfigurer.configureRequest()`. The configurer resolves the search scope - the target indexes and the fields the current user is permitted to read - and applies security policies.
<5> The lambda receives the platform-specific query builder and the resolved `IndexSearchRequestScope`.
<6> Use `scope.getFieldList()` to search only the permitted fields.

[NOTE]
====
Always build the query through `queryConfigurer`. If you configure the request builder directly (for example, with `fields("*")`), the search scope is not resolved and xref:security:resource-roles.adoc#entity-attribute-policy[attribute policies] are not applied, which can make the search return no results.
====

После этого вы можете назначить вашу пользовательскую стратегию компоненту xref:search-field-component.adoc[SearchField] или xref:full-text-filter-component.adoc[FullTextFilter], используя имя стратегии.

[[fts-condition-in-filter-component]]
== Условие полнотекстового поиска в компоненте GenericFilter

Когда дополнение Search добавлено в проект, в диалоговом окне *Add condition* компонента xref:flow-ui:vc/components/genericFilter.adoc[GenericFilter] появляется новое условие:

image:search:add_condition.png[align="center",width="1151"]

В диалоговом окне *Full-text filter condition editor* вы можете определить надпись для полнотекстового фильтра и выбрать стратегию поиска. Если стратегия поиска не выбрана, то используется стратегия по умолчанию.

image:search:condition_editor.png[align="center",width="642"]

Впоследствии записи в компоненте списка, связанном с фильтром, будут фильтроваться на основе результата полнотекстового поиска.
