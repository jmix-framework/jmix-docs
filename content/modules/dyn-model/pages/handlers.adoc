= Обработчики UI

[.since]
Начиная с Jmix 3.1

Обработчик UI добавляет поведение экрану без Java-кода и без повторного развёртывания. Он связывает событие UI, например нажатие кнопки, изменение значения поля или событие жизненного цикла экрана, с коротким выражением. Выражение может читать и изменять редактируемую сущность, менять состояние компонентов, показывать уведомления и диалоги, открывать другие экраны и вызывать методы приложения, которые разработчик сделал доступными.

Обработчики объявляются в списке `handlers` объявления экрана, в YAML или на вкладке *Handlers* диалога экрана. Их можно добавить в следующих экранах:

* экран динамической сущности;
* переопределение экрана статической сущности;
* объявление экрана статической сущности, которое содержит только `handlers` и не содержит `descriptor`. Так можно добавить поведение существующему экрану приложения без изменения его XML.

== Объявление обработчиков

У каждого обработчика есть `event`, `componentId` для событий компонентов и одно выражение `expression`. Следующий пример добавляет обработчики в экран `Customer.detail` приложения. Объявление не содержит `descriptor`, поэтому XML экрана не изменяется:

[source,yaml,indent=0]
----

----

Обработчик `beforeShow` делает поле имени доступным только для чтения для существующих клиентов. Нажатие на `checkNameButton` открывает диалог подтверждения. Когда пользователь нажимает *Yes*, диалог запускает обработчик `doCheckName`, который вызывает операцию приложения `checkCustomerName` и показывает результат. Как определяется операция, см. в разделе <<operations>>.

Несколько обработчиков могут использовать одно и то же событие и компонент. Они выполняются в том порядке, в котором объявлены.

[[events]]
== События

[cols="1,2,1",options="header"]
|===
| Событие | Когда выполняется обработчик | `componentId`

| `click`
| Нажатие на компонент.
| обязателен

| `valueChange`
| Пользователь изменяет значение компонента.
| обязателен

| `init`
| Экран инициализируется.
| не допускается

| `initEntity`
| Экран деталей инициализирует новую сущность. Выполняется только при создании сущности.
| не допускается

| `beforeShow`
| Перед отображением экрана.
| не допускается

| `ready`
| После отображения экрана.
| не допускается
|===

Обработчик без `event` должен иметь `name`. Он не связан ни с каким событием и выполняется, только когда его вызывает диалог подтверждения того же экрана. См. `dialogs.confirm()` ниже.

[[expressions]]
== Выражения

Выражение — это одно выражение {spring-framework-doc}/core/expressions.html[SpEL^]. Чтобы выполнить два действия, объявите два обработчика.

В выражении можно использовать следующие объекты:

[cols="1,3",options="header"]
|===
| Имя | Члены

| `entity`
| Редактируемая сущность экрана деталей или единственная выбранная строка экрана списка. Атрибуты можно читать и записывать: `entity.discount`, `entity.customer.name`.

| `isNew()`
| `true`, если текущая сущность новая и ещё не сохранена.

| `components`
| `setVisible(id, boolean)`, `setEnabled(id, boolean)`, `setRequired(id, boolean)`, `setReadOnly(id, boolean)`, `getValue(id)`, `setValue(id, value)`, `focus(id)`.

| `notifications`
| `show(text)`, `show(title, message)`.

| `dialogs`
| `message(header, text)` показывает сообщение. `confirm(header, text, handlerName)` показывает диалог подтверждения; кнопка *Yes* запускает обработчик с указанным именем в том же экране.

| `navigation`
| `navigate(viewId)`, `navigateToDetail(entity)`, `close()`.

| `services`
| `call(operationName, args...)` вызывает операцию приложения. См. <<operations>>.

| `state`
| `put(key, value)`, `get(key)`, `remove(key)`. Значения хранятся, пока экран открыт, например чтобы передать значение обработчику, вызываемому из диалога подтверждения.

| `event`
| Для `valueChange`: `event.value` и `event.oldValue`. Для других событий: `null`.
|===

Больше в выражении ничего использовать нельзя. Spring-бины, статические методы, конструкторы и другие Java-методы недоступны.

[[operations]]
== Вызов кода приложения

Единственный способ для обработчика вызвать код приложения — это `services.call()`. Разработчик делает метод доступным для обработчиков, добавляя аннотацию `@DynamicModelOperation` с именем операции:

[source,java,indent=0]
----
include::example$/dyn-model-ex1/src/main/java/com/company/sample/app/CustomerOperations.java[tags=operation]
----

Правила для операций:

* Метод должен быть публичным и принадлежать Spring-бину.
* Имена операций должны быть уникальными. Пустое или повторяющееся имя останавливает приложение при запуске.
* Аргументы преобразуются к объявленным типам параметров. Например, `services.call('checkCustomerName', entity)` передаёт редактируемый экземпляр `Customer` в метод выше.
* Операция выполняется в сессии текущего пользователя. Всё, что она делает, подчиняется разрешениям пользователя, включая ограничения ролей уровня строк.
* Возвращаемое значение можно использовать в выражении. Можно читать свойства возвращаемых чисел, строк, сущностей, DTO и коллекций, но нельзя вызывать их методы.

[[handlers-tab]]
== Редактирование обработчиков в административном UI

Обработчики редактируются на вкладке *Handlers* диалога экрана. Диалог обработчика содержит следующие поля:

* *Event* – одно из <<events,событий>>. `initEntity` доступно только для экранов деталей.
* *Component ID* – выпадающий список компонентов экрана с идентификатором и XML-элементом каждого компонента. Список содержит только компоненты, которые может использовать выбранное событие: компоненты, на которые можно нажать, для `click` и компоненты со значением для `valueChange`. Можно также ввести идентификатор, которого нет в списке. Поле доступно только для `click` и `valueChange`.
* *Name* – необязательное имя обработчика, уникальное в пределах экрана. Обязательно для обработчика без события.
* *Expression* – редактор кода с автодополнением. Он предлагает объекты и члены, перечисленные в разделе <<expressions>>, атрибуты сущности после `entity.`, идентификаторы компонентов в методах `components`, имена операций в `services.call()` и имена обработчиков в `dialogs.confirm()`. Автодополнение открывается после точки или при нажатии *Ctrl+Space*.

В таблице обработчиков обработчики одного события и компонента располагаются вместе. Используйте кнопки вверх и вниз, чтобы изменить их порядок в группе.

[[checks]]
== Проверки и ошибки

Обработчики проверяются при применении модели. Применение отклоняется с сообщением, которое объясняет ошибку, в следующих случаях:

* выражение пустое или не может быть разобрано;
* идентификатор компонента отсутствует или задан для события, которое его не допускает;
* компонент с таким идентификатором не существует в экране. Это проверяется, только если объявление экрана содержит XML в `source`;
* у обработчика нет ни события, ни имени;
* два обработчика в экране имеют одинаковое имя;
* `dialogs.confirm()` ссылается на имя обработчика, которого нет в экране;
* `services.call()` ссылается на неизвестную операцию.

Для экрана, сгенерированного из шаблона, и для объявления экрана статической сущности без `descriptor` неверный идентификатор компонента не обнаруживается при применении. Об этом сообщается в логе приложения при открытии экрана.

Если выражение завершается с ошибкой во время выполнения, пользователь видит уведомление о том, что операция не удалась, а экран продолжает работать. Лог приложения содержит идентификатор экрана, обработчик и причину ошибки.
