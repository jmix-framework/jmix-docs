= Определение модели

Экран *Dynamic model* -> *Dynamic model settings* предоставляет административный UI для редактирования динамической модели. Вы добавляете сущности, атрибуты, перечисления и другие элементы через визуальный редактор, а затем применяете изменения с помощью кнопки *Apply*, чтобы проверить их и опубликовать новую версию модели.

Каждый из приведённых ниже разделов показывает YAML, который создаёт редактор для соответствующего элемента — это то же самое определение, которое вы можете просматривать и редактировать напрямую в YAML-представлении редактора.

См. раздел xref:dyn-model:concepts.adoc[], где описано, как работает применение модели и как управляются версии, и xref:dyn-model:yaml-reference.adoc[] — полный справочник по каждому элементу.

[[model-editor]]
== Использование редактора модели

Откройте экран *Dynamic model settings*. Редактор *Visual* представляет текущую модель как структуру связанных таблиц с сущностями, атрибутами, перечислениями, экранами. Вы можете добавлять и редактировать элементы с помощью диалоговых окон.

В любой момент вы можете переключиться на представление *Code*, чтобы просмотреть или отредактировать YAML-определение напрямую; оба представления синхронизированы.

Когда модель готова, нажмите *Apply*. Фреймворк сравнивает отредактированную модель с активной в данный момент и открывает промежуточный экран *Dynamic model changes*, который показывает, что будет применено, прежде чем что-либо будет зафиксировано. В разделе *Model migrations* перечисляются все отдельные изменения — такие как создание сущности, добавление или удаление атрибута либо добавление ограничения уникальности. Если затронуты какие-либо экраны, они перечисляются в разделе *Changed views*.

Просмотрите список и нажмите *Apply changes* для подтверждения. Модель проверяется и, если она корректна, изменения применяются и публикуются как новая версия модели, которая сразу становится активной. Закрытие экрана *Dynamic model changes* без применения отменяет изменения и оставляет активную модель без изменений.

[[attribute-order]]
=== Порядок атрибутов

[.since]
Начиная с Jmix 3.1

На вкладке *Attributes* выберите атрибут и используйте кнопки *Move the attribute up* и *Move the attribute down*, чтобы изменить его позицию. Порядок атрибутов сохраняется в модели. Он определяет порядок полей в сгенерированных экранах деталей и столбцов в сгенерированных экранах списка, а также порядок свойств в метаданных, который используется REST API, инспектором сущностей и компонентом genericFilter. Новый порядок вступает в силу после применения модели.

Перемещать можно только динамические атрибуты. Собственные свойства статической сущности и идентификатор динамической сущности сохраняют свои позиции. Порядок столбцов в базе данных не меняется.

[[model-history]]
=== История модели

[.since]
Начиная с Jmix 3.1

В представлении *Code* нажмите *History*, чтобы увидеть все сохранённые версии модели, начиная с самой новой. Для каждой версии диалог показывает дату, пользователя, который её применил, и является ли она активной. Выберите версию, чтобы увидеть её YAML, и нажмите *Copy to clipboard*, чтобы скопировать его.

Диалог не применяет более раннюю модель. Чтобы вернуться к более ранней версии, скопируйте её YAML, вставьте его в представление *Code* и примените модель.

[[attributes]]
== Атрибуты

Каждый атрибут относится к одному из следующих видов, различающихся по тому, какое поле он определяет: атрибут типа данных, ссылочный атрибут, атрибут-коллекция или атрибут перечисления.

=== Атрибуты типа данных

Атрибут типа данных хранит простое значение, такое как строка, число, дата или булево значение. Вы определяете его, выбирая его тип, который хранится как `javaClass`. Для строковых атрибутов и атрибутов-массивов байтов вы также можете задать `length` и пометить их как большие объекты с помощью `lob`. Атрибут `taxId`, показанный в разделе <<extending-static-entities>>, является атрибутом типа данных.

Полный список поддерживаемых типов см. в секции xref:dyn-model:yaml-reference.adoc#javaclass[поддерживаемые типы].

[[instance-name]]
=== Имя экземпляра

Отметьте *Instance name* для атрибута, чтобы его значение использовалось как xref:data-model:entities.adoc#instance-name[имя экземпляра] сущности. Сущность может иметь только один атрибут имени экземпляра. Если этот флаг уже установлен у другого атрибута, диалог атрибута показывает его имя, и установка флага переносит его на текущий атрибут. Вычисляемый атрибут тоже может быть именем экземпляра.

[[lookup-field]]
==== Поле выбора

[.since]
Начиная с Jmix 3.1

Для одиночной ссылки можно выбрать UI-компонент, который сгенерированные экраны используют для выбора экземпляра, на который указывает ссылка. Задайте его в полях *Lookup field type* и *Lookup actions* диалога атрибута. Атрибут `loyaltyLevel` в примере выше использует выпадающий список.

*Lookup field type* может принимать следующие значения:

* `DROPDOWN` – компонент xref:flow-ui:vc/components/entityComboBox.adoc[entityComboBox]. Элементы загружаются по мере ввода пользователя по имени экземпляра связанной сущности, поэтому этот тип подходит для больших таблиц. Если имя экземпляра связанной сущности не основано на строковых атрибутах, вместо этого поле использует экран выбора.
* `VIEW` – компонент xref:flow-ui:vc/components/entityPicker.adoc[entityPicker], который открывает экран выбора. Если действия не заданы, поле получает стандартные действия выбора и очистки.

Если тип не задан, используется компонент по умолчанию.

*Lookup actions* задаёт кнопки поля: `entity_lookup`, `entity_open`, `entity_clear`.

[[settings-access]]
== Доступ к настройкам модели

Дополнение предоставляет следующие ресурсные роли для экрана *Dynamic model settings*. Назначьте одну из них пользователям, которые работают с моделью.

[cols="1,1,2",options="header"]
|===
| Имя роли | Код | Доступ

| Dynamic model: view settings
| `dynmod-view-settings`
| Открытие настроек модели и истории модели. Модель нельзя изменить.

| Dynamic model: modify settings
| `dynmod-modify-settings`
| Полный доступ. Применение любых изменений, включая изменения, которые удаляют данные.

| Dynamic model: modify settings without data loss
| `dynmod-safe-modify-settings`
| Применение только тех изменений, которые не могут привести к потере сохранённых данных.
|===

[[safe-modify-role]]
=== Изменения без потери данных

[.since]
Начиная с Jmix 3.1

Роль "Dynamic model: modify settings without data loss" позволяет пользователям расширять модель без риска потерять сохранённые данные. Пользователь с этой ролью может редактировать модель в представлениях *Visual* и *Code* и применять следующие изменения: новые сущности, атрибуты, перечисления и значения перечислений, а также изменения валидации, экранов, пунктов меню, сообщений и ресурсных ролей.

Пользователь не может применять изменения, которые могут привести к потере данных:

* удаление применённой сущности или атрибута;
* переименование применённой сущности или атрибута в YAML, так как переименование применяется как удаление и создание;
* удаление применённого перечисления;
* удаление значения из применённого перечисления.

В представлении *Visual* применённые элементы удалить нельзя. Элементы, добавленные после последнего применения, по-прежнему можно удалить. Если редактируемая модель содержит недопустимые изменения, экран *Dynamic model changes* показывает их список, и модель нельзя применить, пока вы не удалите эти изменения.

Ограничение проверяется на сервере. Его нельзя обойти, сохранив настройки модели другим способом, например через инспектор сущностей.
