= Styling

The components are styled the same way as the rest of Jmix: custom properties for the values a design system sets, shadow parts for the internals, and theme variants for the looks the components ship with.

[[custom-properties]]
== Custom Properties

Each component exposes its colors, spacing, and geometry as custom properties in the `+--jmix-ai-*+` namespace. Set them on the component, on a class, or on `:root` to reach every instance:

.XML
[source,xml,indent=0]
----
include::example$/ai-chat-ex1/src/main/resources/com/company/demo/view/styling/styling-view.xml[tags=styled-chat]
----

.CSS
[source,css,indent=0]
----
include::example$/ai-chat-ex1/src/main/resources/META-INF/resources/themes/ai-chat-ex1-aura/view/styling-view.css[tags=knobs]
----

image::aichat-styled-chat.png[A styled chat, align="center", width="1068"]

`--jmix-ai-chat-max-width` is the one worth knowing first. The chat centres its conversation in a column of that width — `768px` by default — so that lines stay readable on a wide screen, and the property resizes the transcript, the composer, and the empty state together. A chat that looks too narrow on a wide monitor is usually this rather than a layout problem.

The rest are per component: `+--jmix-ai-code-block-*+` for a code block's background, syntax palette, icons and radius, `+--jmix-ai-message-input-*+` for the composer's spacing and icons, `+--jmix-ai-message-list-*+` for the transcript and its thinking area.

Each component page lists the parts it exposes: xref:ai-chat:aiCodeBlock.adoc#styling[aiCodeBlock], xref:ai-chat:aiMessageInput.adoc#styling[aiMessageInput], and xref:ai-chat:aiMessageList.adoc#styling[aiMessageList]. `aiChat` exposes none of its own — it is a plain `div`, and the parts you address through it belong to the transcript and the composer inside it.

[[theme-variants]]
== Theme Variants

Some appearances are built in and applied by name through `themeNames`:

[cols="1,3", options="header"]
|===
|Variant
|Effect

|`fixed-toolbar`
|Keeps the composer's controls in a row of their own at all times, instead of only once the text grows.

|`no-header-footer-gap`
|Removes the gap between the composer's bands and its input box, so a band reads as a continuation of the field.

|`input-header-component-always-visible`, `input-footer-component-always-visible`
|Keep a composer band visible while the chat is still empty. See xref:ai-chat:aiChat.adoc#bands[Composer Bands].
|===

A variant applied to `aiChat` reaches the components it composes, so `themeNames="fixed-toolbar"` on the chat configures its composer.

[[themes]]
== Themes

The components ship styled for both Jmix themes, Aura and Lumo, and follow the theme's own tokens for focus rings, borders, radii, and spacing. Dark mode, high-contrast mode, and reduced motion are handled. Layout is expressed in direction-agnostic properties throughout, so the components follow the text direction of the document.

NOTE: `aiChat` has no custom element of its own — it renders as a plain `div`. Style it through the class or id you give it, not by a tag name. The components it contains do have elements of their own, `jmix-ai-message-list` and `jmix-ai-message-input`, as the example above uses.
