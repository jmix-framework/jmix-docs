= aiMessageInput

The `aiMessageInput` component is the composer of a chat: a growing text area with a send button, optional controls beside the field, and optional application content above and below it.

[cols="1h,1", options="autowidth", grid=none, frame=none]
|===
|XML Element
|`aiMessageInput`

|Java Class
|`AiMessageInput`
|===

The component is part of the xref:ai-chat:index.adoc#installation[AI Chat Components] add-on. Use it on its own wherever an application collects a message from the user. xref:ai-chat:aiChat.adoc[aiChat] embeds it and configures it on your behalf, so everything on this page is reachable through the chat as well.

== Overview

The composer keeps its controls on one row while the text fits a single line:

image::aichat-message-input-collapsed.png[Composer in its collapsed state, align="center", width="672"]

Once the text grows past one line, the field takes the full width and the controls reflow into a toolbar row beneath it:

image::aichat-message-input-expanded.png[Composer in its expanded state, align="center", width="672"]

[[submitting]]
== Submitting a Message

The text reaches the application through the submit event:

[source,java,indent=0]
----
include::example$/ai-chat-ex1/src/main/java/com/company/demo/view/messageinput/MessageInputView.java[tags=submit]
----

The event carries the submitted text, and the field clears itself afterwards — the application does not have to.

[NOTE]
====
The composer does not expose the text it holds. There is no `getValue()` or `setValue()`, so the application cannot read what the user is typing, pre-fill the field with a suggested prompt, or clear it early. The text becomes available only when the user submits it.
====

[[text-area]]
== Text Area

----

To pull a band tight against the box, removing the gap that separates them, apply the `no-header-footer-gap` theme variant:

The variant affects both bands at once and leaves the spacing inside the box untouched.

The composer reports focus and blur as a whole:

[source,java,indent=0]
----
include::example$/ai-chat-ex1/src/main/java/com/company/demo/view/messageinput/MessageInputView.java[tags=focus-events]

[[attachments]]
== Attachments

The composer can accept files, by drag and drop or from a file picker, and pass them along with the message. Attachments span several components, so they are described together in xref:ai-chat:attachments.adoc[].

== Attributes

The following attributes are specific to `aiMessageInput`:

[cols="2,5,1", options="header"]
|===
|Name
|Description
|Default

|[[acceptedFileExtensions]]`acceptedFileExtensions`
|Restricts attachments to the listed file extensions. See xref:ai-chat:attachments.adoc[].
|—

|[[acceptedMimeTypes]]`acceptedMimeTypes`
|Restricts attachments to the listed media types. See xref:ai-chat:attachments.adoc[].
|—

|[[attachmentsEnabled]]`attachmentsEnabled`
|Sets whether the composer accepts attachments. See xref:ai-chat:attachments.adoc[].
|`false`

|[[enterAction]]`enterAction`
|Sets what *Enter* does — `SEND` submits the message, `NEWLINE` inserts a line break. See <<text-area,Text Area>>.
|`SEND`

|[[maxFileSize]]`maxFileSize`
|Sets the maximum size of a single attachment in bytes. See xref:ai-chat:attachments.adoc[].
|—

|[[maxFiles]]`maxFiles`
|Sets how many files can be attached to one message. See xref:ai-chat:attachments.adoc[].
|—

|[[maxRows]]`maxRows`
|Sets how many lines the field grows to before it scrolls internally. See <<text-area,Text Area>>.
|`10`

|[[uploadDropZoneEnabled]]`uploadDropZoneEnabled`
|Sets whether files can be dropped onto the composer. See xref:ai-chat:attachments.adoc[].
|—

|[[themeNames]]`themeNames`
|Applies theme variants: `fixed-toolbar` keeps the toolbar layout at all times, `no-header-footer-gap` removes the gap between the bands and the box.
|—

== Elements

An `aiMessageInput` can include `prefix`, `suffix`, `header`, `footer`, `tooltip`, and `i18n` as its nested elements.

[[prefix-suffix-elements]]
=== prefix, suffix

The `prefix` and `suffix` elements each hold one component placed inside the input box, before and after the field. See <<slots,Prefix and Suffix>>.

[[header-footer-elements]]
=== header, footer

The `header` and `footer` elements each hold one component placed inside the composer but outside the input box. See <<bands,Header and Footer Bands>>.

[[i18n-element]]
=== i18n

The `i18n` element re-words this composer. It supports the `placeholder`, `send`, `stop`, and `attach` attributes, each accepting a message key. Omitted attributes keep their values from the message bundle. See <<localization,Localization>>.
