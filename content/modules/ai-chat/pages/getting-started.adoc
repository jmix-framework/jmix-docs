= Начало работы

В этом разделе показано, как добавить работающий AI-чат в приложение: включить server push, подключить модель и добавить компонент.

[[prerequisites]]
== Предварительные требования

Установите дополнение, как описано в разделе xref:ai-chat:index.adoc#installation[Установка].

[[push]]
== Включение server push

Ответы поступают по одному токену и из другого потока, а не из того, который обработал запрос, поэтому в приложении должен быть включен server push. Добавьте `@Push` к классу приложения:

Без этого компоненты отображаются, но ничего из того, что формирует ответ, не доходит до браузера.

[[connecting-a-model]]
== Подключение модели

Чат сам не взаимодействует с моделью. Он запрашивает у приложения одну функцию: получив запрос, вернуть ответ в виде потока текста. Эта функция называется `LLMProvider`, и чат не может отвечать, пока она не задана.

В этом примере используется https://ollama.com[Ollama^], которая запускает модель локально и не требует API-ключа. Добавьте для нее стартер Spring AI:

----

----

Затем задайте чату провайдер. Spring AI автоматически настраивает `ChatClient.Builder`, с помощью которого экран создает свой клиент:

[source,java,indent=0]
----
include::example$/ai-chat-ex1/src/main/java/com/company/demo/view/quickstart/QuickStartView.java[tags=llm-provider]
----

В примере провайдер объявлен с помощью `@Install`, что является обычным способом в экране. `setLlmProvider(...)` делает то же самое из кода, если чат создается программно.

`LLMProvider` находится в пакете `com.vaadin.flow.component.ai.provider`, а не в пакете Jmix.

Запрос содержит не только текст, который ввел пользователь: в нем также есть системный промпт и прикрепленные файлы. Провайдер решает, что из этого передать модели. То, что он не читает, не отправляется. Метод выше передает только сообщение, и этого достаточно для чата, в котором нет ни системного промпта, ни вложений. См. xref:ai-chat:aiChat.adoc#system-prompt[Системный промпт] и xref:ai-chat:attachments.adoc#sending-to-the-model[Отправка файлов модели].

TIP: Всё приведенное выше относится к Ollama только в части стартера и свойств. Чтобы использовать OpenAI, Anthropic, Azure OpenAI или любую другую https://docs.spring.io/spring-ai/reference/api/index.html[модель Spring AI^], замените эти две части, а метод провайдера оставьте без изменений.

[[adding-the-chat]]
== Добавление чата

Объявите компонент в дескрипторе экрана. Задайте ему ширину и высоту. Чат без них подстраивает размер под свое содержимое, что в корневом макете экрана дает узкую колонку:

[source,xml,indent=0]
----
include::example$/ai-chat-ex1/src/main/resources/com/company/demo/view/quickstart/quick-start-view.xml[tags=basics]
----

Это вся конфигурация. Чат хранит диалог в памяти, отображает ответы, и больше ему для работы ничего не нужно:

image::aichat-quickstart.png[Работающий чат, align="center", width="1068"]

[NOTE]
====
Если модель недоступна, приложение запускается как обычно, и экран открывается без ошибок. Сбой проявляется при первом сообщении: в чате отображается неудачная генерация, а не ошибка при запуске.
====

[[next-steps]]
== Что дальше

Чат выше хранит диалог в памяти, поэтому он теряется при закрытии экрана. В разделе xref:ai-chat:aiChat.adoc[] описано, как связать чат с собственной сущностью сообщения, сохранять диалог, управлять генерацией и настраивать части, из которых он состоит.

Компоненты, из которых он состоит, можно использовать и отдельно: xref:ai-chat:aiMessageList.adoc[aiMessageList] для отображения диалога или самостоятельного управления им, xref:ai-chat:aiMessageInput.adoc[aiMessageInput] для ввода сообщения и xref:ai-chat:aiCodeBlock.adoc[aiCodeBlock] для показа кода в любом месте приложения.
