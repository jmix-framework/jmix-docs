= Getting Started

This section shows how to put a working AI chat into an application: enable server push, connect a model, and add the component.

[[prerequisites]]
== Prerequisites

Install the add-on as described in xref:ai-chat:index.adoc#installation[Installation].

[[push]]
== Enabling Server Push

Answers arrive token by token, from a thread other than the one that handled the request, so the application must have server push enabled. Add `@Push` to the application class:

[source,java,indent=0]
----
@Push
@SpringBootApplication
public class DemoApplication {
----

Without it the components render, but nothing an answer produces ever reaches the browser.

[[connecting-a-model]]
== Connecting a Model

The chat does not talk to a model itself. It asks the application for one function — given a request, return the answer as a stream of text — and that function is an `LLMProvider`, installed on the component.

----

`LLMProvider` comes from `com.vaadin.flow.component.ai.provider`, not from a Jmix package.

The request carries more than the text the user typed: it also holds the system prompt and any attached files. The provider decides what of it reaches the model — whatever it does not read is simply not sent. The method above forwards the message alone, which is all a chat with neither of the other two needs. See xref:ai-chat:aiChat.adoc#system-prompt[System Prompt] and xref:ai-chat:attachments.adoc#sending-to-the-model[Sending Files to the Model].

TIP: Nothing above is specific to Ollama except the starter and the properties. To use OpenAI, Anthropic, Azure OpenAI, or any other https://docs.spring.io/spring-ai/reference/api/index.html[Spring AI model^], swap those two and leave the provider method as it is.

[NOTE]
====
The application starts normally when no model is reachable, and the view opens as usual. The failure appears on the first message, as a failed generation in the chat rather than as a startup error.
====

[[next-steps]]
== What Next

The chat above keeps its conversation in memory, so it is gone when the view closes. See xref:ai-chat:aiChat.adoc[] for binding the chat to your own message entity, persisting the conversation, controlling generation, and configuring the parts it is assembled from.

The components it assembles are usable on their own as well: xref:ai-chat:aiMessageList.adoc[aiMessageList] to display a conversation or drive one yourself, xref:ai-chat:aiMessageInput.adoc[aiMessageInput] to collect a message, and xref:ai-chat:aiCodeBlock.adoc[aiCodeBlock] to show code anywhere in the application.
