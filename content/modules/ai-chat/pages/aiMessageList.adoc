= aiMessageList

`aiMessageList` 组件显示一个聊天中的对话。将用户消息渲染为气泡中的纯文本，将助手消息渲染为 Markdown，并带有每条消息的操作、思考指示器和错误横幅。

[cols="1h,1", options="autowidth", grid=none, frame=none]
|===
|XML 元素
|`aiMessageList`

|Java 类
|`AiMessageList`
|===

xref:ai-chat:aiChat.adoc[aiChat] 中嵌入了该组件，因此，在 `aiChat` 中可以使用本页介绍的所有功能。也可单独用来显示已存储的对话，或用基础组件构建自定义的聊天。应用程序可以端到端地显示该列表，如 <<driving,驱动生成的内容>> 所述。

image::aichat-message-list-transcript.png[A conversation in the message list, align="center", width="672"]

应用程序可以针对列表本身完整运行一轮，而无需 `aiChat`。顺序是：追加用户消息，追加一条空的助手消息用于流式写入，将列表切换为 `GENERATING`，在答案回来时追加答案，然后将列表恢复为 `IDLE`。

[source,java,indent=0]
----
include::example$/ai-chat-ex1/src/main/java/com/company/demo/view/messagelist/MessageListView.java[tags=driving]
----
<1> `progress` 在 UI 线程上运行，因为 `appendText` 需要如此。各个块从后台任务发布，并在此处追加。

[IMPORTANT]
====
每一轮的两个环节有不同的线程规则。

`appendText`、`addItem` 和 `setState` 必须在 UI 线程上调用。直接从后台线程调用 `appendText` 会失败，并报出关于会话锁的错误。在上面的示例中，答案块从后台任务发布，并在 `progress` 中追加，而 Jmix 会在 UI 线程上运行 `progress`。

<<thinking-status,下文>> 描述的思考动态是个例外：它会自行获取 UI 锁，因此可以从任何线程调用。
====

[NOTE]
====
思考指示器会附加到正在生成的消息上。当最后一条消息是用户消息时，将列表设置为 `GENERATING`，且不会显示任何内容：没有指示器，也没有错误。然后会先追加一个空的助手消息，指示器就会出现在这个空消息的上面。
====

当列表正在生成时，`getActiveItem()` 返回末尾的助手消息，否则返回 `null`。

[[long-messages]]
== 长消息

较长的用户消息会折叠到一个固定的高度，并带有渐隐效果和 *Show more* 按钮。不折叠助手的消息。

image::aichat-message-list-collapsed.png[已折叠的用户消息, align="center", width="642"]

高度阈值是渲染的高度，而不是字符数，略微超过阈值的消息会完整显示，而不会为了少数几行就折叠。因此，同样的文本可能在窄容器中折叠，而在宽容器中不折叠，因为宽度会决定如何换行。

[[scrolling]]
== 滚动

当答案正在进行流式传输时，列表会将视口保持在底部，以便能显示新出现的文本。

image::aichat-scroll-to-bottom.png[滚动到底部按钮, align="center", width="968"]

当向上滚动时，会脱离这种状态：列表停止跟随，无论期间到达多少内容，都不会强行跳转至新的内容。列表底部会出现一个圆形按钮，用于返回底部；点击后会向下滚动并重新启用跟随，手动向下滚动也会重新启用。但是，以编程方式滚动不会产生状态脱离。

方向键可以将焦点从一条消息移动到另一条消息，并将每条消息滚动到视野中，因此无需鼠标即可阅读对话。

这些组件针对 Jmix 的两种主题 Aura 和 Lumo 都进行了样式设置，并遵循主题自身的焦点环、边框、圆角和间距方面的样式变量，因此上面的属性没有单一的默认值。此外，组件还处理了暗黑模式、高对比度模式以及减弱动画效果，并且其布局采用了与文本方向无关的属性来表示，从而能够自动适应文档的文本书写方向。

== XML 内部元素

一个 `aiMessageList` 可以包含 `thinkingIndicator`、`thinkingStages`、`userActions`、`assistantActions` 和 `i18n` 作为其内部元素。

[[thinkingIndicator-element]]
=== thinkingIndicator

`thinkingIndicator` 元素包含一个组件，用于替换内置的默认指示器。参见 <<thinking-indicator,思考指示器>>。

[[thinkingStages-element]]
=== thinkingStages

`thinkingStages` 元素包含 `thinkingStage` 元素，每个都有一个必需的 `delayMillis` 和一个必需的 `text`，用于定义指示器旁逐步升级的标签。参见 <<thinking-indicator,思考指示器>>。

[[userActions-element]]
=== userActions、assistantActions

这些元素分别包含在用户消息和助手消息上提供的 `action` 元素。每个 `action` 需要一个 `id`，并支持 `type`、`description`、`classNames` 和图标属性。参见 <<actions,消息操作>>。

[[i18n-element]]
=== i18n

`i18n` 元素用于对列表文本进行本地化。支持 `error`、`retry`、`scrollToBottom`、`copy`、`copied`、`showMore` 和 `showLess` 属性，每个属性都支持消息键值，还支持内部的 `codeBlock` 元素，用于对消息内部渲染的代码块进行本地化。参见 <<localization,本地化>>。
