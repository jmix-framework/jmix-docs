= aiMessageList

The `aiMessageList` component is the transcript of a chat. It renders user messages as plain text in a bubble and assistant messages as Markdown, with per-message actions, a thinking indicator, and an error banner.

[cols="1h,1", options="autowidth", grid=none, frame=none]
|===
|XML Element
|`aiMessageList`

|Java Class
|`AiMessageList`
|===

xref:ai-chat:aiChat.adoc[aiChat] embeds it and drives it for you. Use it on its own to display a stored conversation, or to build your own chat out of the base components — the list can be driven by the application from end to end, as described in <<driving,Driving the Generation>>.

== Driving the Generation

An application can run a whole turn against the list itself, without `aiChat`. The sequence is: append the user message, append an empty assistant message to stream into, switch the list to `GENERATING`, append the answer as it arrives, then return the list to `IDLE`.

[source,java,indent=0]
----
include::example$/ai-chat-ex1/src/main/java/com/company/demo/view/messagelist/MessageListView.java[tags=driving]
----
<1> `progress` runs on the UI thread, which is what `appendText` requires — the chunks are published from the background task and appended here.

[IMPORTANT]
====
The two halves of a turn have different threading rules.

`appendText`, `addItem`, and `setState` must be called on the UI thread. Calling `appendText` directly from a background thread fails with an error about the session lock. In the example above the answer chunks are published from the background task and appended in `progress`, which Jmix runs on the UI thread.

The thinking status feed described <<thinking-status,below>> is the exception: it takes the UI lock itself, so it can be called from any thread.
====

[NOTE]
====
The thinking indicator is attached to the message being generated. Setting the list to `GENERATING` while the last message is a user message shows nothing at all — no indicator, no error. Append the empty assistant message first, as above, and the indicator appears on it.
====

`getActiveItem()` returns that trailing assistant message while the list is generating, and `null` otherwise.

[[long-messages]]
== Long Messages

A long user message is collapsed to a fixed height with a fade and a *Show more* toggle. Assistant messages are never collapsed.

image::aichat-message-list-collapsed.png[A collapsed user message, align="center", width="642"]

The threshold is a rendered height, not a number of characters, and a message only slightly over it is shown in full rather than collapsed for the sake of a few lines. The same text may therefore collapse in a narrow container and not collapse in a wide one, because the width decides how it wraps.

[[scrolling]]
== Scrolling

While an answer is streaming, the transcript keeps its viewport at the bottom so that new text stays in view.

image::aichat-scroll-to-bottom.png[The scroll-to-bottom button, align="center", width="968"]

A reader who scrolls up detaches that: the transcript stops following, and content is never pulled away from under them, however much arrives meanwhile. A circular button appears at the bottom of the transcript to go back; clicking it scrolls down and re-engages the following. Scrolling down by hand re-engages it as well, and programmatic scrolling never detaches it.

Arrow keys move focus from message to message, scrolling each into view, so the conversation can be read without a mouse.

[[localization]]
== Localization

The list's own labels — the error banner, the *Retry* button, the scroll-to-bottom button, the copy action, and the *Show more* / *Show less* toggle — come from the add-on's message bundle, under the `+aiMessageList.i18n.*+` keys. Override them in the application's message bundle to re-word every list.

[[styling]]
== Styling

The message list exposes its internals as shadow parts, addressable with the `::part()` selector.

The list itself offers `list`, the error banner's `error`, `error-icon`, `error-text` and `retry-button`, the `scroll-to-bottom-button`, and the thinking area's `thinking`, `dots`, `thinking-label` and `thinking-current`, with `thinking-status-list`, `thinking-status`, `thinking-status-icon`, `thinking-status-text` and `thinking-status-detail` for the status feed.

Each message offers `message`, `content`, `actions`, `action` and `collapse-toggle`, plus `attachments`, `attachment`, `attachment-image`, `attachment-file`, `attachment-preview`, `attachment-icon` and `attachment-name` for what it carries.

The components are styled for both Jmix themes, Aura and Lumo, and follow the theme's own tokens for focus rings, borders, radii, and spacing — which is why the properties above have no single default value. Dark mode, high-contrast mode, and reduced motion are handled, and layout is expressed in direction-agnostic properties, so the components follow the text direction of the document.

== Elements

An `aiMessageList` can include `thinkingIndicator`, `thinkingStages`, `userActions`, `assistantActions`, and `i18n` as its nested elements.

[[thinkingIndicator-element]]
=== thinkingIndicator

The `thinkingIndicator` element holds one component that replaces the built-in indicator. See <<thinking-indicator,Thinking Indicator>>.

[[thinkingStages-element]]
=== thinkingStages

The `thinkingStages` element contains `thinkingStage` elements, each with a required `delayMillis` and a required `text`, which define the escalating label beside the indicator. See <<thinking-indicator,Thinking Indicator>>.

[[userActions-element]]
=== userActions, assistantActions

These elements contain the `action` elements offered on user and assistant messages respectively. An `action` requires an `id` and accepts `type`, `description`, `classNames`, and icon attributes. See <<actions,Message Actions>>.

[[i18n-element]]
=== i18n

The `i18n` element re-words this list. It supports the `error`, `retry`, `scrollToBottom`, `copy`, `copied`, `showMore`, and `showLess` attributes, each accepting a message key, and a nested `codeBlock` element for the code blocks rendered inside its messages. See <<localization,Localization>>.
