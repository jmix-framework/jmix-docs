= User Interface

The `jmix-aitools-flowui-starter` provides a complete chat UI: ready-to-use views, reusable fragments you can embed into your own screens, and the services behind them. Access to the UI is governed by the <<roles,chat user role>>.

[[views]]
== Views

The add-on registers two views out of the box.

[cols="1,1,2", grid=rows, frame=none]
|===
|View |Route |Description

|`AiChatHubView`
|`aitls/chats`
|The chat hub: a landing screen with the message composer, the user's recent conversations and a searchable, date-grouped history. Added to the main menu automatically.

|`AiChatView`
|`aitls/chat/:id?`
|A single conversation. The optional route parameter is the conversation id; opening it without an id starts a new conversation.
|===

Because the add-on contributes a menu item for `AiChatHubView`, users with the chat role get an entry point without any configuration. The menu item is added through the xref:flow-ui:menu-config.adoc[composite menu] mechanism.

[[fragments]]
== Fragments

When the built-in views do not fit your layout, embed the chat UI into your own screens using fragments. A fragment is added to a view descriptor with the `<fragment>` element referencing its class.

[[ai-chat-hub-fragment]]
=== AiChatHubFragment

`io.jmix.aitoolsflowui.view.chathub.AiChatHubFragment` is the self-contained chat hub used by `AiChatHubView`. Drop it into any view to get the composer, recent chats and history in one component:

[source, xml, indent=0]
----
include::example$/ai-tools-ex1/src/main/resources/com/company/onboarding/view/assistant/assistant-view.xml[tags=embed-hub]
----

Its public API:

* `setRecentChatsCount(int)` — overrides how many recent chats are shown next to the composer. When unset, the value comes from the xref:ai-tools:properties.adoc#jmix.aitools.ui.chat-hub-recent-chats-count[`jmix.aitools.ui.chat-hub-recent-chats-count`] application property.
* `setMarkIconSupplier(SerializableSupplier<Component>)` — replaces the brand mark icon shown on the hub and on conversation cards.

[[ai-chat-fragment]]
=== AiChatFragment

`io.jmix.aitoolsflowui.view.chat.AiChatFragment` is the conversation panel used by `AiChatView`: a title row, the message timeline and the composer, bound to one conversation. Embed it and bind a conversation programmatically:

[source, xml, indent=0]
----
<fragment id="chatFragment"
          class="io.jmix.aitoolsflowui.view.chat.AiChatFragment"/>
----

[source, java, indent=0]
----
@ViewComponent
private AiChatFragment chatFragment;

@Autowired
private AiConversationService conversationService;

@Subscribe
public void onInit(final InitEvent event) {
    AiConversation conversation = conversationService.create();
    chatFragment.setConversation(conversation);
}
----

Key methods:

* `setConversation(AiConversation)` / `setConversationId(UUID)` — bind the panel to a conversation.
* `sendMessage(String)` — submit a user message programmatically.
* `setReadOnly(boolean)` — hide the composer and the title-edit button.
* `setMessageInputEnabled(boolean)` / `focusMessageInput()` — control the composer.
* `isAwaitingResponse()` — whether a reply is currently being generated.
* `setAiAvatarIconSupplier(SerializableSupplier<Component>)` — customize the assistant avatar.

[[ai-chat-input-fragment]]
=== AiChatInputFragment

`io.jmix.aitoolsflowui.view.input.AiChatInputFragment` is the reusable message composer: a text area plus a send button. Enter submits the message, Shift+Enter inserts a newline. It is used inside the two fragments above, and you can embed it on its own when you build a custom chat layout. Configure it with `setSubmitHandler(Consumer<String>)`, `setPlaceholder(String)`, `setInputEnabled(boolean)`, `focus()` and `clear()`.

[[services]]
== Services

The UI is backed by three services. They operate on the UI models `AiConversation` and `AiChatMessage` and are implicitly scoped to the current user.

[cols="1,3", grid=rows, frame=none]
|===
|Service |Responsibility

|`AiChatService`
|Generates the assistant's reply to a user message. `processMessage(message)` returns the reply; an overload accepts a `Consumer<AiToolStatusUpdate>` to receive progress. `isAvailable()` reports whether replies can be produced (that is, whether a model is configured).

|`AiConversationService`
|Manages the current user's conversations: `loadConversations()`, `loadConversation(id)`, `create()`, `save(conversation)`, `remove(conversation)`.

|`AiChatMessageService`
|Manages the messages of a conversation: `createMessage(...)`, `loadMessages(conversation)`, `loadLatestMessage(...)`.
|===

[[persistence]]
=== Persistence and Empty Implementations

Where these services store data depends on which starter is present:

* With `jmix-aitools-flowui-data-starter`, the services are backed by JPA entities and conversations and messages are persisted in the database.
* With only `jmix-aitools-flowui-starter`, the services are no-op stubs: `AiChatService.isAvailable()` returns `false`, nothing is persisted and the chat is effectively disabled. This lets the UI render before persistence is in place.

To use the chat with a non-default storage, provide your own beans implementing `AiChatService`, `AiConversationService` and `AiChatMessageService` instead of adding the data starter.

[[icon-provider]]
=== Icon Provider

The brand icon shown on the hub and the assistant avatar is supplied by the `AiIconProvider` bean. Replace this bean to change the add-on's iconography globally, or override it per fragment with the icon-supplier setters shown above.

[[roles]]
== Security Role

The add-on provides one predefined xref:security:resource-roles.adoc[resource role].

[cols="1,3", grid=rows, frame=none]
|===
|Name |`AI Tools: chat user`
|Code |`aitools-chat-user`
|Scope |UI
|===

It grants an end user access to the chat: the chat hub and the conversation view, and management of their own conversations and messages — starting, continuing, renaming and deleting chats. Concretely, the role grants:

* view access to `AiChatHubView` and `AiChatView`, and the menu item for the chat hub;
* full access to the user's own conversations and create/read access to their messages.

Assign this role to every user who should be able to use the assistant. See xref:security:users.adoc[] for how to assign roles to users.

NOTE: The role grants access to the chat UI only — it does not widen data access. When the assistant loads business data through the predefined xref:ai-tools:tools.adoc#data-loading[data-load tools], the queries run under the current user's own xref:security:index.adoc[data access] permissions, so the role does not let a user read anything they could not read otherwise. Any custom tools you add are responsible for their own access control.
