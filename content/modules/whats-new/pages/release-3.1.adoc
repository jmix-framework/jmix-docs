= Релиз 3.1

[NOTE]
====
В данный момент доступен только релиз-кандидат Jmix 3.1. Для работы с ним установите xref:studio:install.adoc#nightly[ночную сборку] Studio 3.1.

Документация по релизу в процессе обновления.
====

[IMPORTANT]
====
Для создания новых проектов в Jmix 3.1 или для апгрейда существующего проекта требуется Studio 3.1 или более поздней версии, поэтому в первую очередь xref:studio:update.adoc[обновите] плагин Jmix Studio.

Минимальная требуемая версия IntelliJ IDEA / OpenIDE - 2026.1.
====

Раздел xref:studio:project.adoc#upgrading-project[Апгрейд проекта] содержит информацию о том, как обновить проект с помощью Studio. Процедура автоматической миграции вносит следующие изменения в ваш проект:

* Обновляет версию Jmix BOM, которая, в свою очередь, определяет версии всех зависимостей.
* Обновляет версию Jmix Gradle plugin.
* Обновляет версию Gradle wrapper до 9.8.0

См. полный список <<breaking-changes,критических изменений>>, которые могут затронуть ваш проект после обновления.

[[studio-improvements]]
=== Улучшения Studio

* В xref:studio:view-wizard.adoc#creating-entity-based-views[мастере создания экранов] для экранов списка и экранов master-detail появился новый шаг, на котором выбирается способ фильтрации данных пользователями: xref:flow-ui:vc/components/genericFilter.adoc[genericFilter] (по умолчанию), набор компонентов xref:flow-ui:vc/components/propertyFilter.adoc[propertyFilter] для выбранных атрибутов, xref:flow-ui:vc/components/fullTextFilter.adoc[fullTextFilter], если в проект включено дополнение Search, или отсутствие фильтра.

* xref:studio:entity-designer.adoc[Дизайнер сущностей] позволяет задать аннотацию xref:data-model:entities.adoc#lookup-field[@LookupField] для сущности и для её ссылочных атрибутов. Мастер создания экранов учитывает эту аннотацию при генерации компонентов для ссылок.

* Новое действие *Views with Attribute* дизайнера сущностей показывает компоненты экранов, связанные с атрибутом сущности, и открывает дескриптор экрана на выбранном компоненте. Оно также позволяет добавить атрибут в экраны сущности. Действие доступно на панели инструментов таблицы атрибутов и в каждой строке атрибута.

* Новое действие *Copy View* создает копию экрана вместе с его контроллером, дескриптором и сообщениями.

* Диалог со списком changelog-файлов Liquibase, еще не примененных к базе данных, теперь показывает содержимое выбранного changelog-файла. С его помощью можно просматривать changelog-файлы, которые поставляются с дополнениями.

* xref:studio:jpql-designer.adoc[Дизайнер JPQL] можно открыть с помощью иконки на левом поле редактора для запросов в `LoadContext.Query` и в методе `setQueryString()`.

* Инспекции Studio проверяют структуру отчетов, определенных в Java-коде и содержащих xref:reports:creation/bands.adoc#streaming-bands[потоковый бэнд]. Они сообщают о структуре, которую не поддерживает движок отчетов, например, о втором потоковом бэнде, дочернем бэнде потокового бэнда или наборе данных, отличном от SQL или JPQL.

[[ai-chat]]
=== Новое дополнение AI Chat

Новое дополнение xref:ai-chat:index.adoc[AI Chat] предоставляет UI-компоненты для создания интерфейсов AI-чата. Ответы формирует `LLMProvider`, реализуемый приложением, поэтому компоненты работают со Spring AI, SDK поставщика модели или вашим собственным сервисом.

* xref:ai-chat:aiChat.adoc[aiChat] — полноценный чат с потоковой выдачей ответов, сообщениями в формате Markdown, вложенными файлами и действиями для отдельных сообщений. Его можно связать с контейнером данных вашей собственной сущности сообщения, чтобы сохранять переписку.
* xref:ai-chat:aiMessageList.adoc[aiMessageList] и xref:ai-chat:aiMessageInput.adoc[aiMessageInput] можно использовать по отдельности, чтобы создать чат, возможности которого выходят за рамки `aiChat`.
* xref:ai-chat:aiCodeBlock.adoc[aiCodeBlock] отображает исходный код в сообщениях чата или в любом другом экране.

[[ui-recovery]]
=== Новое дополнение UI Recovery

Новое дополнение xref:ui-recovery:index.adoc[UI Recovery] сохраняет несохраненные изменения экранов, если сервер перезапускается, истекает HTTP-сессия или закрывается браузер. Во время работы пользователя оно сохраняет изменения в базу данных в виде черновика и предлагает восстановить черновик, когда пользователь снова открывает экран. Черновики доступны в кластере и после полного перезапуска приложения.

[[dynamic-model]]
=== Дополнение Dynamic Model

Дополнение xref:dyn-model:index.adoc[Dynamic Model] больше не является экспериментальным. В нём появились следующие новые возможности:

* xref:dyn-model:handlers.adoc[Обработчики UI] добавляют поведение экранам: это короткие выражения, которые выполняются при нажатии кнопок, изменении значений и событиях экранов и могут вызывать методы приложения, помеченные аннотацией `@DynamicModelOperation`.
* xref:dyn-model:search.adoc[Полнотекстовый поиск] индексирует динамические атрибуты, помеченные как `searchable`.
* xref:dyn-model:concepts.adoc#cluster[Поддержка кластера]: модель, применённая на одном узле, применяется на всех остальных узлах.
* Роль xref:dyn-model:defining-model.adoc#safe-modify-role[Dynamic model: modify settings without data loss] позволяет пользователям применять только те изменения, которые не могут привести к потере сохранённых данных.
* xref:dyn-model:defining-model.adoc#model-history[История модели] показывает все применённые версии модели.
* Можно изменять xref:dyn-model:defining-model.adoc#attribute-order[порядок атрибутов].
* Для ссылочных атрибутов можно задать xref:dyn-model:defining-model.adoc#lookup-field[тип и действия поля выбора].
* Пункты меню динамических экранов могут иметь xref:dyn-model:views.adoc#menu-items[иконку].
* Кнопка *Generate XML* xref:dyn-model:views.adoc#generate-xml[рендерит шаблон экрана в XML], который можно редактировать.
* Динамические сущности и атрибуты отображаются в экранах xref:dyn-model:concepts.adoc#data-tools[Data Tools].

[[ai-tools]]
=== Дополнение AI Tools

В дополнении xref:ai-tools:index.adoc[AI Tools] появилась аннотация xref:ai-tools:tools.adoc#exclude-from-ai[@ExcludeFromAi], которая на уровне кода скрывает сущность или атрибут от инструментов Data Load. В отличие от include- и exclude-свойств `jmix.aitools.dataload.*`, аннотацию нельзя переопределить при развёртывании.

[[bpm]]
=== Дополнение BPM

В xref:bpm:menu-views/modeler-web.adoc[BPMN-моделере] дополнения xref:bpm:index.adoc[BPM] появились следующие новые возможности:

* Можно задавать уровень истории процесса (*History level*) вместе с другими xref:bpm:bpmn/bpmn-process.adoc#properties[свойствами процесса]. Выбранный уровень переопределяет xref:bpm:history.adoc#history-levels[уровень истории] движка процессов.
* Можно задавать атрибуты `flowable:exclusive`, `flowable:asyncLeave` и `flowable:asyncLeaveExclusive` для задач, встроенных подпроцессов, элементов call activity, шлюзов и большинства событий. Для пользовательских задач, шлюзов и событий теперь доступен и атрибут `flowable:async`. См. раздел xref:bpm:bpmn/transactions.adoc#asynchronous-execution-properties[Asynchronous Execution Properties].
* Можно добавлять в процессы xref:bpm:bpmn/bpmn-events.adoc#escalation-events[события эскалации], задавать их свойства и управлять определениями эскалаций (*Escalation definitions*) в xref:bpm:bpmn/bpmn-process.adoc#escalation-definition[свойствах процесса].

[[reports]]
=== Дополнение Reports

В дополнении xref:reports:index.adoc[Reports] появились следующие новые возможности:

* Бэнд отчёта теперь может быть xref:reports:creation/bands.adoc#streaming-bands[потоковым]: его строки читаются из курсора базы данных и записываются в документ XLSX по одной, а не загружаются в память. Чтобы сделать бэнд потоковым, установите для бэнда флажок *Streaming* на экране деталей отчёта или задайте `streaming = true` в аннотации `@BandDef`.
* Новый тип набора данных xref:reports:creation/bands.adoc#structure_llm[AI-generated JPQL] позволяет описать данные бэнда на естественном языке. На экране деталей отчёта LLM генерирует по промпту JPQL-запрос, который хранится в определении отчёта. При запуске отчёта сохранённый запрос выполняется через `DataManager` с учётом разрешений текущего пользователя на доступ к данным.

[[grouping-data-grid]]
=== Дополнение Grouping Data Grid

Чтобы сохранять применённые xref:flow-ui:vc/components/groupDataGrid.adoc#column-filtering[фильтры по заголовкам колонок] в параметрах запроса URL, добавьте элемент xref:flow-ui:facets/urlQueryParameters.adoc#groupDataGridFilter[`groupDataGridFilter`] в фасет xref:flow-ui:facets/urlQueryParameters.adoc[`urlQueryParameters`].

[[email]]
=== Дополнение Email Sending

Дополнение xref:email:index.adoc[Email Sending] упрощает настройку xref:email:authentication.adoc#oauth2-authentication[аутентификации OAuth2] для почтовых серверов Google и Microsoft:

* Новый экран xref:email:menu-views/email-connection.adoc[Email connection] заменяет экран *OAuth2 token*. Он подключает почтовый ящик через Authorization Code Flow или, для Microsoft, через Device Code Flow и сохраняет refresh-токен. Экран также показывает параметры подключения и проверяет подключение к почтовому серверу.
* Новое свойство xref:email:configuration.adoc#jmix.email.oauth2.redirect-uri[jmix.email.oauth2.redirect-uri] задаёт redirect URI для Authorization Code Flow, например, если приложение работает за обратным прокси.
* Дополнение само задаёт механизм аутентификации `XOAUTH2`, поэтому добавлять его в `spring.mail.properties.*` не нужно.

[[read-views]]
=== Экраны чтения

Новые xref:flow-ui:views/view-classes.adoc#standard-read-view[экраны чтения] показывают экземпляр сущности, который пользователи не могут редактировать. Экран чтения наследуется от `StandardReadView`, загружает сущность по её идентификатору и всегда имеет `DataContext` только для чтения.

* Экраны чтения можно создавать в Studio с помощью шаблонов *Entity read view* и *DTO entity read view* xref:studio:view-wizard.adoc#creating-entity-based-views[мастера создания экранов].
* Экраны чтения можно открывать с помощью бинов xref:flow-ui:views/opening-views.adoc#navigation[ViewNavigators] и xref:flow-ui:views/opening-views.adoc#reading-entities[DialogWindows], а также бина xref:tabbed-mode:opening-views.adoc#opening-read-views[ViewBuilders] дополнения Tabbed Application Mode.
* Если у сущности есть экран чтения, действие xref:flow-ui:actions/list-actions.adoc#list_read[list_read] открывает его вместо экрана деталей в режиме только для чтения. Новое действие xref:flow-ui:actions/entity-picker-actions.adoc#entity_read[entity_read] показывает сущность, выбранную в компоненте выбора сущностей.
* Аннотация xref:flow-ui:views/view-templates.adoc#read-view-template[@ReadViewTemplate] генерирует экран чтения для сущности во время выполнения. Дополнение Dynamic Model генерирует экраны чтения для динамических сущностей, в которых xref:dyn-model:yaml-reference.adoc#dynamic-entity-views[объявлен экран] с `type: read`.

[[resizable-side-panel]]
=== Изменение размера боковой панели

Теперь пользователь может xref:flow-ui:vc/layouts/sidePanelLayout.adoc#resizing[изменять размер компонента `sidePanelLayout`] во время работы приложения, перетаскивая разделитель у внутреннего края панели. Для горизонтальных положений изменяется ширина, для вертикальных — высота. Размер не выходит за заданные минимальный и максимальный пределы. Фасет xref:flow-ui:facets/settings.adoc[`settings`] сохраняет и восстанавливает выбранный пользователем размер.

[[popover-renderer]]
=== PopoverRenderer для DataGrid

Новый xref:flow-ui:vc/components/dataGrid.adoc#popover-renderer[рендерер всплывающего окна] показывает длинный текст в колонке `dataGrid`. Текст в ячейке обрезается многоточием, если не помещается, а при нажатии на ячейку полный текст показывается во всплывающем окне. Добавьте элемент `popoverRenderer` в колонку в XML или создайте `PopoverRenderer` в Java-коде.

[[lookup-field]]
=== Аннотация @LookupField

Новая аннотация сущности xref:data-model:entities.adoc#lookup-field[@LookupField] определяет компонент, который фреймворк генерирует для выбора ссылки: `entityComboBox` с выпадающим списком или `entityPicker`, который открывает экран выбора. Она она учитывается при генерации параметров `genericFilter` и `propertyFilter`, редактируемых ячеек `dataGrid` и в шаблонах экранов времени выполнения. Поместите аннотацию на класс сущности, чтобы применить ко всем ссылкам на эту сущность, или на ссылочный атрибут, чтобы применить только к этому атрибуту. Также можно задать действия компонента и загружать элементы выпадающего списка порциями по мере ввода текста пользователем – с помощью JPQL-запроса или поиска по имени экземпляра.

Элемент `itemsQuery` компонента `entityComboBox` получил новый атрибут xref:flow-ui:vc/components/entityComboBox.adoc#items-query-by-instance-name[byInstanceName], который находит элементы по имени экземпляра без JPQL-запроса.

[[breaking-changes]]
== Критические изменения

[[vaadin-25-3]]
=== Vaadin 25.3

Обновление до Vaadin 25.3 приносит следующие изменения (см. https://github.com/jmix-framework/jmix/issues/5720[#5720^]):

* Компонент xref:flow-ui:vc/html-components/image.adoc[image] больше не может содержать другие компоненты. У `JmixImage` больше нет методов `setText()`/`getText()`, `setWhiteSpace()`, `setEnabled()`/`isEnabled()`, `add()` и `remove()`. В XML атрибуты `enabled`, `text` и `whiteSpace`, а также вложенные компоненты `image` игнорируются.

* Удалён защищённый метод `JmixMenuBarRootItem.updateClassName()`.

* `InMemoryUploadHandler` и `FileTemporaryStorageUploadHandler` теперь наследуются от `AbstractUploadHandler` из Vaadin вместо `TransferProgressAwareHandler`. `FileTemporaryStorageUploadHandler` удаляет временный файл, если загрузка завершилась ошибкой или была отклонена, а его метод `getFileInfo()` возвращает `null`, пока текущая загрузка не создаст файл.

* В дополнении xref:tabbed-mode:index.adoc[Tabbed Application Mode] конфигурация `@Push` оболочки приложения (app shell) применяется до вызова слушателей `UIInitListener`, поэтому слушатель может её переопределить.

* `Anchor.setHref()` и `IFrame.setSrc()`, а также XML-атрибуты `href` и `src` компонентов `anchor` и `iframe` выбрасывают `IllegalArgumentException` для схемы URL, которую Vaadin не считает безопасной, например `javascript:`. Добавьте схему в параметр конфигурации Vaadin `safeUrlSchemes` или используйте в коде `setUnsafeHref()` и `setUnsafeSrc()`.

* `addThemeName("")` выбрасывает `IllegalArgumentException`.

* Методы `expand()`, `collapse()`, `expandRecursively()` и `collapseRecursively()` компонента `TreeGrid` теперь принимают параметры `Collection<? extends T>` и `Stream<? extends T>`. Обновите сигнатуры этих методов, если вы переопределяете их в подклассе `TreeDataGrid`.

* Многие константы `VaadinIcon` и соответствующие им константы `JmixFontIcon` объявлены устаревшими. Метод `setRole()` класса `JmixSideDialog` объявлен устаревшим, вместо него используйте `setAriaRole()`. Метод `withOverlayRole()` интерфейса `Dialogs.SideDialogBuilder` объявлен устаревшим, вместо него используйте `withAriaRole()`.

[[ai-tools-breaking-changes]]
=== Дополнение AI Tools

* Строки, возвращаемые `JpqlExecutionResult.getRows()` и `EntityDataLoadResult.getRows()`, теперь содержат `null` для колонки, у которой нет значения (см. https://github.com/jmix-framework/jmix/issues/5598[#5598^]). Раньше такая колонка содержала пустую строку. Строки, которые инструменты возвращают модели, также содержат `null` вместо пустой строки. Сигнатуры методов не изменились, поэтому компилятор не покажет места, которые нужно исправить. Проверяйте значения на `null` при чтении строк:
+
[source,java]
----
EntityDataLoadResult result = aiDataLoadService.loadData("customers with their email");
for (Map<String, Object> row : result.getRows()) {
    Object email = row.get("email");
    String text = email != null ? email.toString() : ""; // email может быть null
}
----

* `EntityDataLoadResult.getQuery()` теперь возвращает запрос, который был фактически выполнен или не прошёл валидацию (см. https://github.com/jmix-framework/jmix/issues/5749[#5749^]). Если сгенерированный запрос был исправлен, метод возвращает исправленный запрос, а его объяснение, предупреждения, `maxResults` и `firstResult` берутся из результата исправления. Исходный запрос, сгенерированный LLM, получить из результата нельзя.

* В интерфейсе `AiChatMessageService` появился новый метод `loadLatestMessages()` (см. https://github.com/jmix-framework/jmix/issues/5649[#5649^]). Если у вас есть собственная реализация этого интерфейса, реализуйте этот метод. Хаб чатов теперь сортирует и группирует беседы по времени последнего сообщения, а не по времени создания.

[[charts-breaking-changes]]
=== Дополнение Charts

Дополнение xref:charts:index.adoc[Charts] теперь использует Apache ECharts 6.1 вместо 5.4 (см. https://github.com/jmix-framework/jmix/issues/5699[#5699^]). Существующие экраны работают без изменений кода, но диаграммы могут выглядеть иначе:

* В теме по умолчанию используются новая цветовая палитра и новые отступы. Легенда расположена внизу по центру, а заголовок — вверху по центру. Чтобы получить вид, близкий к предыдущей версии, задайте `colorPalette="#5470c6, #91cc75, #fac858, #ee6666, #73c0de, #3ba272, #fc8452, #9a60b4, #ea7ccc"` для `charts:chart`, `top="0"` для `charts:legend` и `left="0" top="0"` для `charts:title`. Проверьте диаграммы, у которых есть компоненты вверху или внизу, например слайдер `dataZoom`: они могут перекрывать заголовок или легенду.

* Подписи и названия осей теперь остаются внутри диаграммы, а названия осей сдвигаются так, чтобы не перекрывать подписи осей. Чтобы вернуть прежнее поведение, задайте `outerBoundsMode="NONE"` для `charts:gridItem` или `nameMoveOverlap="false"` для оси.

* Стили форматированного текста (rich text) наследуют настройки шрифта и тени текста обычной подписи. Чтобы вернуть прежнее поведение, добавьте `"richInheritPlainLabel": false` в `nativeJson`.

* Фигуры bar, pictorialBar, candlestick и boxplot больше не выходят за пределы сетки. Чтобы вернуть прежнее поведение, задайте `containShape="false"` для оси.

* Второй аргумент функции `valueFormatter` всплывающей подсказки теперь является индексом в исходных данных серии, а не индексом после фильтрации `dataZoom`. Обновите JavaScript-функции, которые его используют.

* `Grid.containLabel` объявлен устаревшим. Вместо него используйте `outerBoundsMode="SAME"` вместе с `outerBoundsContain="AXIS_LABEL"`. Когда `containLabel` включён, параметры `outerBounds*` игнорируются.

[[email-breaking-changes]]
=== Дополнение Email Sending

* Экран *OAuth2 token* заменён новым экраном подключения, а его идентификатор изменён с `email_tokenView` на `email_connectionView` (см. https://github.com/jmix-framework/jmix/issues/5546[#5546^]). Старый маршрут `email/token` по-прежнему работает. Замените старый идентификатор экрана:
** в `menu.xml`, если приложение использует режим единого меню. Иначе при открытии главного экрана возникнет исключение `NoSuchViewException`.
** в аннотациях `@ViewPolicy` и `@MenuPolicy` ваших ресурсных ролей. Иначе пользователи потеряют доступ к экрану.

* Дополнение больше не определяет бин `mailSendTaskExecutor` (см. https://github.com/jmix-framework/jmix/issues/5703[#5703^]). Раньше Vaadin мог использовать этот бин для своей асинхронной работы, а приложение не запускалось, если в нём был другой бин `TaskExecutor`. Теперь:
** Код, который инжектирует бин `mailSendTaskExecutor` по имени, при запуске завершается ошибкой `NoSuchBeanDefinitionException`. Удалите такие инжекции.
** Ваш собственный бин с именем `mailSendTaskExecutor` больше не заменяет пул отправки писем. Дополнение игнорирует его и при запуске записывает в лог предупреждение.
** Методы `@Async` и асинхронные задачи Vaadin выполняются в бине `applicationTaskExecutor` из Spring Boot, а не в пуле отправки писем. У этого пула другой размер и неограниченная очередь.

* Если аутентификация OAuth2 включена, дополнение строже проверяет конфигурацию (см. https://github.com/jmix-framework/jmix/issues/5539[#5539^]):
** Свойство `spring.mail.password` игнорируется, а дополнение записывает в лог предупреждение. Раньше пароль, заданный вместе с аутентификацией OAuth2, переключал дополнение на базовую аутентификацию.
** Приложение не запускается, если не задано одно из свойств `spring.mail.username`, `jmix.email.oauth2.client-id` или `jmix.email.oauth2.secret`. Раньше эти ошибки проявлялись только при отправке письма.

[[maps-breaking-changes]]
=== Дополнение Maps

Удалением объектов карты теперь управляет атрибут `featureDeleteEnabled` векторного источника, отдельно от режима изменения (см. https://github.com/jmix-framework/jmix/issues/5576[#5576^]):

* Источник с `featureModifyEnabled="true"` больше не показывает действие *Delete* по умолчанию. Задайте `featureDeleteEnabled="true"` для источника или установите свойство приложения `jmix.maps.ui.feature-modify-includes-delete` в `true`, чтобы сохранить прежнее поведение для всех источников, в которых не задан `featureDeleteEnabled`.

* `SourceFeatureDeleteEvent` и `addSourceFeatureDeleteListener()` перенесены из `HasFeatureModify` в `HasFeatureDelete`. Замените в своём коде `HasFeatureModify.SourceFeatureDeleteEvent` на `HasFeatureDelete.SourceFeatureDeleteEvent`.

[[oidc-saml-breaking-changes]]
=== Дополнения OIDC и SAML

Следующие элементы автоконфигурации переименованы (см. https://github.com/jmix-framework/jmix/issues/5484[#5484^]):

* `OidcAutoConfiguration.DefaulOidcVaadinWebSecurity` -> `DefaultOidcVaadinWebSecurity`
* `SamlAutoConfiguration.DefaulSamlVaadinWebSecurity` -> `DefaultSamlVaadinWebSecurity`
* Бин `claimsRoleMapper` в `SamlAutoConfiguration` -> `samlAssertionRolesMapper`

Обновите код, который наследует эти классы или обращается к бину по имени.

[[reports-breaking-changes]]
=== Дополнение Reports

Из дополнения xref:reports:index.adoc[Reports] удалён неиспользуемый код, пришедший из библиотеки YARG (см. https://github.com/jmix-framework/jmix/issues/2774[#2774^]):

* Класс `io.jmix.reports.yarg.loaders.impl.GroovyDataLoader`. Для типа загрузчика `groovy` дополнение использует `JmixGroovyDataLoader`. В отличие от удалённого класса, он проверяет свойства `jmix.core.unsafe-runtime-features-enabled` и `jmix.reports.groovy-enabled`.

* Методы `update()` и `batch()` класса `io.jmix.reports.yarg.util.db.QueryRunner`. Вместо них используйте Spring `JdbcTemplate` или JDBC.
* Методы `commitAndClose()`, `commitAndCloseQuietly()`, `rollback()`, `rollbackAndClose()`, `rollbackAndCloseQuietly()`, `loadDriver()`, `printStackTrace()` и `printWarnings()` класса `io.jmix.reports.yarg.util.db.DbUtils`.
* Метод `UnoConverter.createAny(Object)`. Вместо него используйте `new Any(new Type(XCell.class), value)`.
* Поля `AbstractFormatter.SIMPLE_ALIAS_REGEXP` и `DataExtractorImpl.EMPTY_MAP`.

[[dynamic-model-yaml]]
=== Дополнение Dynamic Model

Дополнение Dynamic Model теперь читает YAML-определение модели строго (см. https://github.com/jmix-framework/jmix/issues/5731[#5731^]). Правила описаны в разделе xref:dyn-model:yaml-reference.adoc#writing-yaml[Написание YAML вручную].

Это касается только моделей, которые были написаны или отредактированы вручную в представлении *Code*. Модели, сохранённые из визуального редактора, всегда содержат значения в кавычках и читаются как раньше.

[[entity-reference-loaded-state]]
=== Состояние загруженности ссылок на сущности

Экземпляр сущности, возвращаемый методом `DataManager.getReference()`, теперь сообщает как загруженные только свой идентификатор и атрибуты, которые были установлены в нём позже (см. https://github.com/jmix-framework/jmix/issues/5660[#5660^]). Раньше `EntityStates.isLoaded()` возвращал `true` для любого атрибута такого экземпляра.

Теперь для ссылки:

* `isLoaded()` возвращает `false` для всех атрибутов, кроме идентификатора и атрибутов, установленных после создания.
* `isLoadedSafe()` возвращает `YES` или `NO` и не вызывает геттеры.
* `isLoadedWithFetchPlan()` возвращает `false` для фетч-плана, который содержит другие атрибуты.
* `getCurrentFetchPlan()` возвращает фетч-план с идентификатором и атрибутами, установленными после создания.

Это приводит к следующим видимым последствиям:

* Ссылка сериализуется (в REST, в переменных процессов BPM и т.д.) только со своим идентификатором и установленными в ней атрибутами.
* Ссылка не получает значения по умолчанию, которые присваиваются при создании в методах `@PostConstruct` или в инициализаторах полей.
* `DataContext.merge()` ссылки в контекст, в котором уже есть загруженный экземпляр, не заменяет загруженные значения на null.

Если ваш код рассчитывал на то, что ссылка сообщает все атрибуты как загруженные, обновите его.
