= Релиз 3.1

[IMPORTANT]
====
Для создания новых проектов в Jmix 3.1 или для апгрейда существующего проекта требуется Studio 3.1 или более поздней версии, поэтому в первую очередь xref:studio:update.adoc[обновите] плагин Jmix Studio.

Минимальная требуемая версия IntelliJ IDEA / OpenIDE - 2026.1.
====

Раздел xref:studio:project.adoc#upgrading-project[Апгрейд проекта] содержит информацию о том, как обновить проект с помощью Studio. Процедура автоматической миграции вносит следующие изменения в ваш проект:

* Обновляет версию Jmix BOM, которая, в свою очередь, определяет версии всех зависимостей.
* Обновляет версию Jmix Gradle plugin.
* Обновляет версию Gradle wrapper до 9.8.0

См. полный список <<breaking-changes,критических изменений>>, которые могут затронуть ваш проект после обновления.

== Новая и улучшенная функциональность

[[studio-improvements]]
=== Улучшения Studio

[[read-views]]
=== Экраны чтения

Новые xref:flow-ui:views/view-classes.adoc#standard-read-view[экраны чтения] показывают экземпляр сущности, который пользователи не могут редактировать. Экран чтения наследуется от `StandardReadView`, загружает сущность по её идентификатору и всегда имеет `DataContext` только для чтения.

* Экраны чтения можно создавать в Studio с помощью шаблонов *Entity read view* и *DTO entity read view* xref:studio:view-wizard.adoc#creating-entity-based-views[мастера создания экранов].
* Экраны чтения можно открывать с помощью бинов xref:flow-ui:views/opening-views.adoc#navigation[ViewNavigators] и xref:flow-ui:views/opening-views.adoc#reading-entities[DialogWindows], а также бина xref:tabbed-mode:opening-views.adoc#opening-read-views[ViewBuilders] дополнения Tabbed Application Mode.
* Если у сущности есть экран чтения, действие xref:flow-ui:actions/list-actions.adoc#list_read[list_read] открывает его вместо экрана деталей в режиме только для чтения. Новое действие xref:flow-ui:actions/entity-picker-actions.adoc#entity_read[entity_read] показывает сущность, выбранную в компоненте выбора сущностей.
* Аннотация xref:flow-ui:views/view-templates.adoc#read-view-template[@ReadViewTemplate] генерирует экран чтения для сущности во время выполнения. Дополнение Dynamic Model генерирует экраны чтения для динамических сущностей, в которых xref:dyn-model:yaml-reference.adoc#dynamic-entity-views[объявлен экран] с `type: read`.

[[resizable-side-panel]]
=== Изменение размера боковой панели

Теперь пользователь может xref:flow-ui:vc/layouts/sidePanelLayout.adoc#resizing[изменять размер компонента `sidePanelLayout`] во время работы приложения, перетаскивая разделитель у внутреннего края панели. Для горизонтальных положений изменяется ширина, для вертикальных — высота. Размер не выходит за заданные минимальный и максимальный пределы. Фасет xref:flow-ui:facets/settings.adoc[`settings`] сохраняет и восстанавливает выбранный пользователем размер.

[[popover-renderer]]
=== PopoverRenderer для DataGrid

Новый xref:flow-ui:vc/components/dataGrid.adoc#popover-renderer[рендерер всплывающего окна] показывает длинный текст в колонке `dataGrid`. Текст в ячейке обрезается многоточием, если не помещается, а при нажатии на ячейку полный текст показывается во всплывающем окне. Добавьте элемент `popoverRenderer` в колонку в XML или создайте `PopoverRenderer` в Java-коде.

[[ui-recovery]]
=== Дополнение UI Recovery

Новое дополнение xref:ui-recovery:index.adoc[UI Recovery] сохраняет несохраненные изменения экранов, если сервер перезапускается, истекает HTTP-сессия или закрывается браузер. Во время работы пользователя оно сохраняет изменения в базу данных в виде черновика и предлагает восстановить черновик, когда пользователь снова открывает экран. Черновики доступны в кластере и после полного перезапуска приложения.

[[dynamic-model]]
=== Дополнение Dynamic Model

Дополнение xref:dyn-model:index.adoc[Dynamic Model] больше не является экспериментальным. В нём появились следующие новые возможности:

* xref:dyn-model:handlers.adoc[Обработчики UI] добавляют поведение экранам: это короткие выражения, которые выполняются при нажатии кнопок, изменении значений и событиях экранов и могут вызывать методы приложения, помеченные аннотацией `@DynamicModelOperation`.
* xref:dyn-model:search.adoc[Полнотекстовый поиск] индексирует динамические атрибуты, помеченные как `searchable`.
* xref:dyn-model:concepts.adoc#cluster[Поддержка кластера]: модель, применённая на одном узле, применяется на всех остальных узлах.
* Роль xref:dyn-model:defining-model.adoc#safe-modify-role[Dynamic model: modify settings without data loss] позволяет пользователям применять только те изменения, которые не могут привести к потере сохранённых данных.
* xref:dyn-model:defining-model.adoc#model-history[История модели] показывает все применённые версии модели.
* Можно изменять xref:dyn-model:defining-model.adoc#attribute-order[порядок атрибутов].
* Для ссылочных атрибутов можно задать xref:dyn-model:defining-model.adoc#lookup-field[тип и действия поля выбора].
* Пункты меню динамических экранов могут иметь xref:dyn-model:views.adoc#menu-items[иконку].
* Кнопка *Generate XML* xref:dyn-model:views.adoc#generate-xml[рендерит шаблон экрана в XML], который можно редактировать.
* Динамические сущности и атрибуты отображаются в экранах xref:dyn-model:concepts.adoc#data-tools[Data Tools].

[[bpm]]
=== Дополнение BPM

В xref:bpm:menu-views/modeler-web.adoc[BPMN-моделере] дополнения xref:bpm:index.adoc[BPM] появились следующие новые возможности:

* Можно задавать уровень истории процесса (*History level*) вместе с другими xref:bpm:bpmn/bpmn-process.adoc#properties[свойствами процесса]. Выбранный уровень переопределяет xref:bpm:history.adoc#history-levels[уровень истории] движка процессов.
* Можно задавать атрибуты `flowable:exclusive`, `flowable:asyncLeave` и `flowable:asyncLeaveExclusive` для задач, встроенных подпроцессов, элементов call activity, шлюзов и большинства событий. Для пользовательских задач, шлюзов и событий теперь доступен и атрибут `flowable:async`. См. раздел xref:bpm:bpmn/transactions.adoc#asynchronous-execution-properties[Asynchronous Execution Properties].
* Можно добавлять в процессы xref:bpm:bpmn/bpmn-events.adoc#escalation-events[события эскалации], задавать их свойства и управлять определениями эскалаций (*Escalation definitions*) в xref:bpm:bpmn/bpmn-process.adoc#escalation-definition[свойствах процесса].

[[grouping-data-grid]]
=== Дополнение Grouping Data Grid

Чтобы сохранять применённые xref:flow-ui:vc/components/groupDataGrid.adoc#column-filtering[фильтры по заголовкам колонок] в параметрах запроса URL, добавьте элемент xref:flow-ui:facets/urlQueryParameters.adoc#groupDataGridFilter[`groupDataGridFilter`] в фасет xref:flow-ui:facets/urlQueryParameters.adoc[`urlQueryParameters`].

[[reports]]
=== Дополнение Reports

Бэнд отчёта теперь может быть xref:reports:creation/bands.adoc#streaming-bands[потоковым]: его строки читаются из курсора базы данных и записываются в документ XLSX по одной, а не загружаются в память. Чтобы сделать бэнд потоковым, установите для бэнда флажок *Streaming* на экране деталей отчёта или задайте `streaming = true` в аннотации `@BandDef`.

[[breaking-changes]]
== Критические изменения

[[dynamic-model-yaml]]
=== Dynamic Model: более строгое чтение YAML

Дополнение Dynamic Model теперь читает YAML-определение модели строго (см. https://github.com/jmix-framework/jmix/issues/5731[#5731^]). Правила описаны в разделе xref:dyn-model:yaml-reference.adoc#writing-yaml[Написание YAML вручную].

Это касается только моделей, которые были написаны или отредактированы вручную в представлении *Code*. Модели, сохранённые из визуального редактора, всегда содержат значения в кавычках и читаются как раньше.
