= Release 3.1

[[upgrade]]
== How To Upgrade

[IMPORTANT]
====
To create new projects with Jmix 3.1 or to upgrade an existing project, you need Studio 3.1 or newer, so xref:studio:update.adoc[update] your Jmix Studio plugin first.

Jmix Studio 3.1 requires IntelliJ IDEA 2026.1 or newer.
====

See xref:studio:project.adoc#upgrading-project[Upgrading Project] section for how to upgrade your project using Studio. The automatic migration procedure makes the following changes in your project:

* Updates the version of Jmix BOM which in turn defines versions of all dependencies.
* Updates the version of Jmix Gradle plugin.
* Updates Gradle wrapper to 9.8.0

See also the full list of <<breaking-changes,breaking changes>> that can affect your project after the upgrade.

[[dynamic-model]]
=== Dynamic Model Add-on

The xref:dyn-model:index.adoc[Dynamic Model] add-on is no longer experimental. It has the following new features:

* xref:dyn-model:handlers.adoc[UI handlers] add behavior to views: short expressions that run on button clicks, value changes and view events, and can call application methods marked with `@DynamicModelOperation`.
* xref:dyn-model:search.adoc[Full-text search] indexes dynamic attributes marked as searchable.
* xref:dyn-model:concepts.adoc#cluster[Cluster support]: a model applied on one node is applied on all other nodes.
* The xref:dyn-model:defining-model.adoc#safe-modify-role[Dynamic model: modify settings without data loss] role lets users apply only changes that cannot lose stored data.
* The xref:dyn-model:defining-model.adoc#model-history[model history] shows all applied versions of the model.
* You can change the xref:dyn-model:defining-model.adoc#attribute-order[order of attributes].
* You can set the xref:dyn-model:defining-model.adoc#lookup-field[lookup field type and actions] for reference attributes.
* Menu items of dynamic views can have an xref:dyn-model:views.adoc#menu-items[icon].
* The *Generate XML* button xref:dyn-model:views.adoc#generate-xml[renders a view template into XML] that you can edit.
* Dynamic entities and attributes are shown in the xref:dyn-model:concepts.adoc#data-tools[Data Tools] views.

[[breaking-changes]]
== Breaking Changes

[[dynamic-model-yaml]]
=== Dynamic Model: Stricter Reading of YAML

The Dynamic Model add-on now reads the YAML model definition strictly (see https://github.com/jmix-framework/jmix/issues/5731[#5731^]). The rules are described in xref:dyn-model:yaml-reference.adoc#writing-yaml[Writing YAML by Hand].

This affects only models that were written or edited by hand in the *Code* presentation. Models saved from the visual editor always have quoted values and are read as before.

Check your model before the upgrade:

* A model that has `yes`, `no`, `on`, `off`, `1` or `0` in a boolean field, such as `required` or `unique`, or that has a duplicate key, now fails to read. The active model is applied at application start, so the application does not start, and the model settings view cannot open the model. Fix such a model before the upgrade.
* A constraint parameter such as `inclusive: no` is now read as text, and applying the model fails. Use `inclusive: false`.
* Unquoted values that were changed before are now read as written. This is important for enumeration value IDs. For example, `id: 0755` was applied as `493`, and the database rows contain `493`. Now the ID is read as `0755`, or as `755` if all IDs of the enumeration are integers, so these rows do not match any enumeration value. To keep the existing data, change the ID in the model to the value that was applied before, for example `id: "493"`.

[[dynamic-model-java-api]]
=== Dynamic Model: Java API for Model Definitions

New fields were added to the records that describe a dynamic model in Java code. This affects only applications that create model definitions in Java code:

* `DynamicViewDefinition` has new `readEntityContainerId` and `handlers` components.
* `DynamicAttributeDefinition` has a new `lookup` component.
* `MenuItemDefinition` has a new `icon` component.

Code that calls the constructors of these records must be updated. Code that uses the factory methods and builders of the `DynamicModelDefinitions` class works without changes.

The `DynamicViewType` enums in the `io.jmix.dynmodel.meta` and `io.jmix.dynmodelflowui.model` packages have a new `READ` value for xref:dyn-model:views.adoc#read-views[read views]. A `switch` expression that lists all values must get a branch for it.
