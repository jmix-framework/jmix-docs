[[notification-expressions]]
=== Выражения в уведомлениях

Тема и текст — это https://www.flowable.com/open-source/docs/bpmn/ch04-API/#expressions[выражения^] Flowable, например `+${order.number}+` или `+${context.recipientUser.username}+`. Значения вставляются с помощью `toString()`, поэтому для форматирования вызывайте методы, например `+${order.date.getYear()}+`.

У объекта `context` есть следующие свойства:

[cols="1,4", options=header]
|===
|Свойство
|Описание

|`recipientUser`
|Пользователь, который получает это уведомление.

|`processId`
|Id экземпляра процесса.

|`processDefinitionId`, `processDefinitionName`
|Id и имя определения процесса.

|`executionId`
|Id исполнения.

|`variables`
|Map переменных процесса, например `+${context.variables.orderNumber}+`.
|===

NOTE: В теме и тексте `context` всегда означает контекст уведомления, даже если у процесса есть переменная с таким именем.

[[notification-templates]]
=== Шаблоны сообщений в уведомлениях

Если уведомление использует шаблон сообщения, шаблон формирует только текст. Тема по-прежнему берется из свойства *Subject* и использует выражения Flowable, а шаблон использует синтаксис xref:message-templates:index.adoc#message-template-engine[FreeMarker].

xref:message-templates:message-templates.adoc#parameters[Параметры] шаблона заполняются из переменных процесса: алиас каждого параметра должен совпадать с именем переменной процесса. Например, если у процесса есть переменная `order`, добавьте параметр `order` и используйте `+${order.number}+` в шаблоне. Объект `context`, описанный в разделе <<notification-expressions>>, тоже доступен. Значения параметров по умолчанию не используются. Если шаблон ссылается на отсутствующую переменную, уведомление не отправляется, а ошибка записывается в лог.

[[notification-errors]]
=== Ошибки в уведомлениях

Уведомления не прерывают процесс. Если выражение завершается ошибкой или уведомление не удается отправить, ошибка записывается в лог и процесс продолжается. Другие уведомления и другие получатели того же уведомления не затрагиваются.

Уведомления в приложении сохраняются в отдельной транзакции, поэтому остаются, даже если транзакция процесса позже откатывается. Электронные письма отправляются асинхронно дополнением xref:email:index.adoc[Email Sending]. Получатель без адреса электронной почты не получает письмо, а в лог записывается предупреждение.
