= Flowable API

Jmix BPM uses the xref:bpm:introduction.adoc#flowable-bpm[Flowable] process engine. Your code works with processes through the Flowable API.

[[flowable-api]]
== Process Engine Services

The process engine provides its API as services. The following table lists the Flowable services and shows which of them Jmix BPM uses. For details on the Flowable services, see https://www.flowable.com/open-source/docs/bpmn/ch04-API#the-process-engine-api-and-services[The Process Engine API and services^] in the Flowable documentation.

[cols="1,2,2", options="header"]
|===
|Flowable service
|What it does
|Used by Jmix BPM

|`RepositoryService`
|Deploys processes, queries process definitions, suspends and activates them.
|Yes. See <<process-definitions>>.

|`RuntimeService`
|Starts process instances, reads and changes process variables, sends messages and signals.
|Yes. See <<starting-process-programmatically>>.

|`TaskService`
|Queries, claims, assigns and completes user tasks.
|Yes, as `BpmTaskService`, which extends `TaskService`.

|`HistoryService`
|Queries the data of running and finished process instances, tasks and variables.
|Yes. See xref:bpm:history.adoc[].

|`ManagementService`
|Queries and runs jobs, such as timers and asynchronous continuations.
|Yes. See xref:bpm:job-executor.adoc[].

|`ProcessMigrationService`
|Migrates process instances to another version of the process definition.
|Yes, for xref:bpm:instance-migration.adoc[instance migration].

|`DynamicBpmnService`
|Changes properties of a deployed process definition without a new deployment.
|No.

|`FormService`
|Works with Flowable start and task forms.
|No. Jmix BPM has its own xref:bpm:forms.adoc[process forms].

|`IdentityService`
|Manages Flowable users and groups.
|No. Jmix BPM takes users from the application and user groups from the xref:bpm:menu-views/user-groups.adoc[User Groups] view.
|===

Jmix BPM adds its own services in the `io.jmix.bpm.service` package:

[cols="1,4", options="header"]
|===
|Jmix BPM service
|What it does

|`BpmTaskService`
|The task service of the engine. It extends `TaskService` with the `completeTaskWithOutcome()` method. See <<using-bpm-task-service>>.

|`UserGroupService`
|Returns all user groups, the groups of a user and the users of a group.

|`BpmExpressionEvaluatorService`
|Evaluates an expression for a process execution or with the given variables.

|`BpmModelService`
|Returns the extension properties of a BPMN element in a process definition. See xref:bpm:bpmn/bpmn-elements.adoc#extension-properties[Extension Properties].

|`SendEmailService`
|Sends an email. The xref:bpm:bpmn/jmix-email-task.adoc[] uses it. Available when the project has the Email add-on.
|===

The following method completes an order approval task with the `approve` outcome:

[source,java,indent=0]
----
include::example$/bpm-ex1/src/main/java/com/company/bpmex1/app/OrderApprovalService.java[tags=bpm-task-service;complete-task]
----
<1> `completeTaskWithOutcome()` adds the outcome to this map, so don't pass an immutable map, such as `Map.of()`.
<2> `approve` is the outcome id.
