= Задача отправки уведомления
:page-aliases: bpm:sending-notifications.adoc

[.since]
Начиная с Jmix 3.1

[[overview]]
== Обзор

*Задача отправки уведомления* отправляет уведомления в приложении и по электронной почте через дополнение xref:notifications:index.adoc[Notifications]. Когда процесс доходит до задачи, она отправляет все свои уведомления, а затем процесс продолжается.

Это собственная задача Jmix, а не стандартная задача BPMN. Чтобы добавить ее, нажмите значок *Change type* image:quick-start/change-type-icon.png[width="20"] задачи и выберите *Send Notification Task*.

Чтобы отправлять уведомления при событиях пользовательской задачи, например при ее назначении, используйте вместо этого xref:bpmn/bpmn-user-task.adoc#notifications[уведомления пользовательской задачи].

.*Графическая нотация*
Задача отправки уведомления изображается как прямоугольник со скругленными углами и небольшим значком колокольчика в левом верхнем углу.

image::jmix-notification-task/notification-task.png[,150]

.*XML-представление*
Задача отправки уведомления — это сервисная задача с типом `jmix-send-notification`. Ее уведомления — элементы расширения `jmix:notification`.

[source,xml]
----
<serviceTask id="notify-manager" name="Notify manager" flowable:type="jmix-send-notification">
  <extensionElements>
    <jmix:notification recipientType="expression" recipientExpression="${order.manager}"
                       channels="in-app,email" contentType="plain">
      <jmix:subject>New order ${order.number}</jmix:subject>
      <jmix:body>Order ${order.number} is waiting for your approval.</jmix:body>
    </jmix:notification>
  </extensionElements>
</serviceTask>
----

[[notifications]]
== Уведомления

Задача отправляет уведомления через дополнение xref:notifications:index.adoc[Notifications], поэтому это дополнение обязательно. Без него моделер показывает сообщение об ошибке при выборе задачи отправки уведомления, а во время выполнения задача не отправляет уведомления, и процесс продолжается.

Другие дополнения расширяют эти возможности:

* xref:email:index.adoc[Email Sending] включает канал *Email*. См. xref:notifications:configuration.adoc#email-channel[Канал Email].
* xref:message-templates:index.adoc[Message Templates] позволяет формировать текст из шаблона. См. <<notification-templates>>.

Чтобы выбирать тип уведомления в моделере, зарегистрируйте типы, как описано в разделе xref:notifications:configuration.adoc#notification-types[Типы уведомлений]. Чтобы читать уведомления в приложении, получателям нужна роль, описанная в разделе xref:notifications:configuration.adoc#roles[Роли безопасности].

[[notification-properties]]
=== Свойства уведомления

Раздел *Notifications* показывает список уведомлений. Для управления ими используйте кнопки *Create*, *Edit* и *Remove*. У уведомления есть следующие свойства:

[cols="1,6", grid=rows, frame=none]
|===
|*Свойство*
|*Описание*

|Subject
|Тема уведомления. Обязательное свойство. Может содержать <<notification-expressions,выражения>>.

|Type
|Необязательный тип уведомления. Задает значок уведомления в UI. Список показывает xref:notifications:configuration.adoc#notification-types[зарегистрированные типы]; также можно ввести имя типа.

|Recipient
|Кто получает уведомление. Обязательное свойство. См. <<notification-recipients>>.

|Recipient expression
|Выражение, которое возвращает получателей. Показывается, если *Recipient* имеет значение *Expression*.

|Channels
|*In-app*, *Email* или оба. Нужен хотя бы один канал. По умолчанию выбран *In-app*. *Email* доступен, если установлено дополнение xref:email:index.adoc[Email Sending].

|Use message template, Message template
|Шаблон, по которому формируется текст. Доступно, если установлено дополнение xref:message-templates:index.adoc[Message Templates]. См. <<notification-templates>>.

|Content type
|*Plain text* или *HTML*. Для HTML текст редактируется в редакторе форматированного текста. Если переключиться с HTML на обычный текст, моделер запрашивает подтверждение и очищает текст. Скрыто, если используется шаблон сообщения.

|Body
|Текст уведомления. Может содержать <<notification-expressions,выражения>>. Скрыто, если используется шаблон сообщения.
|===

В XML каждое уведомление — это элемент расширения `jmix:notification`. Его атрибуты: `recipientType`, `recipientExpression`, `channels`, `type`, `contentType` и `templateCode`; дочерние элементы: `jmix:subject` и `jmix:body`.

[[notification-recipients]]
=== Получатели уведомлений

[cols="1,1,4", options=header]
|===
|Recipient
|Значение в XML
|Описание

|Process initiator
|`initiator`
|Пользователь, сохраненный в переменной процесса xref:bpmn/bpmn-user-task.adoc#assign-task-by-process-variable[initiator].

|Expression
|`expression`
|Результат *Recipient expression*. Выражение может возвращать имя пользователя, пользователя или их коллекцию, например `+${order.manager}+` или `+${reviewers}+`.
|===

Каждый получатель получает отдельное уведомление, а тема и текст формируются для этого получателя. Пользователь получает одно уведомление, даже если выражение возвращает его несколько раз. Имя пользователя, которому не соответствует существующий пользователь, пропускается.
