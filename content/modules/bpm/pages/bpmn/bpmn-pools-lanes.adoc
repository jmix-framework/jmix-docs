= Участники, полосы и модели сотрудничества
:page-aliases: bpm:bpmn/bpmn-collaboration.adoc

Участник (pool) представляет сторону в модели сотрудничества, а полоса (lane) — часть участника, например роль или отдел. Для выполнения процесса участник не нужен.

image::bpmn-pool-lanes/pool-lanes.png[,460]

[[pools]]
== Участники

Когда вы добавляете участника на экране Modeler, он охватывает все элементы диаграммы.

image::bpmn-pool-lanes/adding-pool.png[]

WARNING: При удалении участника удаляются все элементы внутри него.

Если на диаграмме есть участник и не выбран ни один элемент, панель свойств показывает свойства модели сотрудничества, *Id* и *Name*, вместо свойств процесса.

image::bpmn-pool-lanes/collaboration-properties.png[,810]

Чтобы задать свойства процесса, выберите участника. У участника есть свойства *Id* и *Name* и группа *Process* со xref:bpmn/bpmn-process.adoc#properties[свойствами процесса].

image::bpmn-pool-lanes/process-properties.png[,810]

В XML при добавлении участника создается элемент `collaboration` с элементом `participant`:

[source,xml]
----
<collaboration id="Collaboration_16sinaz">
    <participant id="Participant_1txu04k" processRef="pool-demo" />
</collaboration>
<process id="pool-demo" name="Pool demo" isExecutable="true">
    <startEvent id="Event_0yeospn">
      <outgoing>Flow_1snk2tn</outgoing>
    </startEvent>
    <sequenceFlow id="Flow_1snk2tn" sourceRef="Event_0yeospn" targetRef="Activity_187mecy" />
    <userTask id="Activity_187mecy">
      <incoming>Flow_1snk2tn</incoming>
    </userTask>
</process>
----

[[collaboration-model]]
== Модели сотрудничества

Несколько участников образуют модель сотрудничества. В XML элемент `collaboration` содержит элемент `participant` для каждого участника, а атрибут `processRef` участника ссылается на id его процесса.

image::bpmn-pool-lanes/collaboration-two-processes.png[,700]

При развертывании модели сотрудничества каждый процесс развертывается как отдельное определение процесса со своим id. Все они появляются в списке определений процессов, и любой из них можно запустить.

image::bpmn-pool-lanes/process-definitions-wiindow.png[,650]

Потоки сообщений между участниками только документируют, как взаимодействуют процессы. Движок не отправляет по ним сообщения. Чтобы отправить сообщение процессу, вызовите API движка из своего кода. См. xref:bpmn/bpmn-events.adoc#sending-messages[Отправка сообщений].

Модель сотрудничества показывает связанные процессы на одной диаграмме. Например, основной процесс и процесс, который он вызывает из нескольких мест:

image::bpmn-collaboration/collaboration-example-1.png[,800]

Здесь потоки сообщений только показывают, что один и тот же процесс вызывается из разных точек основного процесса.

Другой пример показывает процессы, которые обмениваются сообщениями и сигналами:

image::bpmn-collaboration/collaboration-example-2.png[,800]

Здесь процесс *One* отправляет сообщение, чтобы запустить процесс *Two*, а затем ждет сообщения от процесса *Two*. Или срабатывает событие таймера, и сигнал от процесса *One* запускает процесс *Three*.

[[lanes]]
== Полосы

В Jmix BPM полоса может задавать исполнителя и кандидатов для пользовательских задач, которые на ней расположены. Пользовательская задача без исполнителя и без групп-кандидатов получает исполнителя, пользователей-кандидатов и группы-кандидатов своей полосы. См. xref:bpmn/bpmn-user-task.adoc#assigning-task-by-lane[Назначение задач по полосе].
