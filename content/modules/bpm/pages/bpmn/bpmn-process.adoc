= Процесс

Процесс — это структурированный поток действий или задач, служащий конкретной бизнес-цели.
В BPMN процесс — центральный элемент, который объединяет все связанные элементы и показывает весь рабочий процесс и взаимодействия в бизнес-контексте.

== Графическая нотация

У процесса нет визуального представления. Его можно поместить в xref:bpmn/bpmn-pools-lanes.adoc#pools[участника], чтобы модель была нагляднее, но это не обязательно.

== XML-представление

В XML процесс представлен элементом `process`.

[source,xml]
----
  <process id="new-process" name="New process" isExecutable="true" >
    . . .
  </process>
----

// Additionally, the process may have `processType`, `isClosed`, and `definitionalCollaborationRef` attributes that are ignored in Jmix BPM.

== Свойства

В моделере BPMN, когда на холсте не выбран ни один элемент, можно задать следующие свойства процесса:

[cols="1,6", grid=rows, frame=none]
|===
|*Свойство*
|*Описание*
|Process id
|*Process id* идентифицирует процесс после развертывания. Во время выполнения он называется *process key*.
|Name
|Имя процесса, не более 255 символов.
|Candidate groups
|Группа пользователей, которым разрешено запускать процесс. Если пользователь входит в группу, он видит это определение процесса на экране xref:menu-views/start-process-view.adoc[Start process].
|Candidate users
|Отдельные пользователи, которым разрешено запускать процесс. Если пользователь входит в число кандидатов, он видит это определение процесса на экране xref:menu-views/start-process-view.adoc[Start process].
|Event listeners
|См. xref:bpm:jmix-listeners.adoc#execution-listeners[Слушатели выполнения].
|Signal definitions [[signal-definition]]
a|Чтобы создать определение сигнала, задайте его *Id*, *Name* и *Scope*:

* Сигналы `Global` передаются по всему движку процессов. Если один экземпляр процесса генерирует событие сигнала, на него могут отреагировать другие экземпляры процессов. Это полезно для взаимодействия разных процессов.
* Сигналы `Process instance` действуют только внутри своего экземпляра процесса. С их помощью можно синхронизировать взаимоисключающие задачи.

xref:bpmn/bpmn-events.adoc#signal-events[Событие сигнала] можно настроить так, чтобы оно ссылалось на определение.
|Message definitions
|Чтобы создать определение сообщения, задайте его id и имя. Это сообщение можно использовать в xref:bpmn/bpmn-events.adoc#message-events[событиях сообщения].
|Error definitions
|Чтобы создать определение ошибки, задайте его id и имя. Кроме того, можно задать Error code. Эту ошибку можно использовать в xref:bpmn/bpmn-events.adoc#error-events[событиях ошибки].
|Escalation definitions [[escalation-definition]]
a|Чтобы создать определение эскалации, задайте его *Id*, *Name* и при необходимости *Escalation code*. Генерирующие и перехватывающие xref:bpmn/bpmn-events.adoc#escalation-events[события эскалации] ссылаются на определение и сопоставляются друг с другом по его коду. См. xref:bpmn/bpmn-events.adoc#escalation-matching[Сопоставление эскалаций].

[.since]
Начиная с Jmix 3.1
|History level
a|Уровень истории для экземпляров этого процесса: *None*, *Instance*, *Task*, *Activity*, *Audit* или *Full*. *Default* означает, что используется уровень истории движка процессов. См. xref:bpm:history.adoc#history-levels[Уровни истории].

[.since]
Начиная с Jmix 3.1
