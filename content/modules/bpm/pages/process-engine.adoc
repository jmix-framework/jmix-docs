= Process Engine
:page-aliases: bpm-components.adoc

The process engine deploys process definitions, runs process instances and stores their state in the database.
Jmix BPM uses the xref:bpm:introduction.adoc#flowable-bpm[Flowable] process engine.
The engine runs jobs, such as asynchronous continuations and timers, with the xref:bpm:job-executor.adoc[job executor] and records the xref:bpm:history.adoc[history] of process instances.
To work with the engine from your code, use the xref:bpm:jmix-bpm-api.adoc#flowable-api[Flowable API].

[[process-engine-configuration]]
== Process Engine Configuration

Jmix BPM includes the Flowable Spring Boot starter, which creates the process engine.
You can change engine settings with the `flowable.*` https://www.flowable.com/open-source/docs/bpmn/ch05a-Spring-Boot#flowable-application-properties[application properties^].
For a setting that has no application property, create a Spring bean that implements `EngineConfigurationConfigurer<SpringProcessEngineConfiguration>`.
See https://www.flowable.com/open-source/docs/bpmn/ch05a-Spring-Boot#customizing-engine-configuration[Customizing Engine Configuration^] in the Flowable documentation.

CAUTION: Jmix BPM configures the process engine with its own configurer, `BpmSpringProcessEngineConfigurationConfigurer`. Jmix BPM sets the typed event listeners, the custom default and post BPMN parse handlers, the activity behavior factory, the task service and the start process instance interceptor. If your custom configurer replaces any of them, Jmix BPM features can stop working, often without an error.
