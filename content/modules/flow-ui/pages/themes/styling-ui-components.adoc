= Styling UI Components

Vaadin and Jmix components provide several ways to change their appearance. Start with the highest-level option that meets your needs and write custom CSS only when necessary.

Use the following order:

. Select the xref:themes/themes.adoc[application theme].
. Use a built-in component theme variant.
. Change a component or theme CSS property.
. Write a CSS rule to style certain part of the component.

This order reduces custom CSS and makes styles easier to maintain after a framework update.

[[application-theme]]
== Application Theme

The application theme defines the default appearance and the available theme properties, component theme variants, and utility classes.

See xref:themes/aura.adoc#customizing-aura[Customizing Aura] and xref:themes/lumo.adoc#customizing-lumo[Customizing Lumo].

[[style-variants]]
== Component Theme Variants

Many components provide built-in theme variants that change color, size, or another part of their appearance. Apply component theme variants using the `themeNames` XML attribute or a Java API such as `addThemeVariants()` and `addThemeNames()`.

[source,xml,indent=0]
----
<hbox>
    <button text="Primary" themeNames="primary"/>
    <button text="Success" themeNames="success"/>
    <button text="Tertiary" themeNames="tertiary"/>
</hbox>
----

.Buttons with applied theme variants
image::themes/button-theme-variants.png[align="center", width="316"]

IMPORTANT: Aura and Lumo do not support exactly the same component theme variants. Component reference pages indicate whether each theme variant is supported by Aura, Lumo, or both.

[[customizing-theme-variants]]
=== Customizing Component Theme Variants

To override the built-in component theme variant, use a CSS rule that targets its value in the `theme` attribute:

.my-project.css
[source,css,indent=0]
----
vaadin-button[theme~="primary"] {
    background-color: purple;
}
----

[[css-properties]]
[[component-properties]]
== Component CSS Properties

Vaadin components provide CSS properties with the `--vaadin-` prefix. These properties are the main API for changing component styles.

Set a property on the `html` element to change all instances of a component:

.my-project.css
[source,css]
----
html {
    --vaadin-button-border-radius: 1em;
    --vaadin-input-field-background: white;
}
----

Set the same property on a component selector to limit the change to that component type or a class:

.my-project.css
[source,css]
----
vaadin-text-field.search-field {
    --vaadin-input-field-border-radius: 2em;
}
----

Component reference pages list the supported CSS properties and selectors.

[[writing-css]]
== Writing CSS Rules

Vaadin and Jmix components are more complex than native HTML elements. Many internal elements are located in the https://developer.mozilla.org/en-US/docs/Web/API/Web_components/Using_shadow_DOM[shadow DOM^]. The shadow DOM prevents global CSS from changing internal elements by accident.

.Component HTML element structure
image::themes/element-shadow-dom.png[align="center", width="698"]

[[class-names]]
=== CSS Classes

Use the `classNames` XML attribute or the `addClassName()` Java method to apply a CSS class to a component instance.

[source,xml,indent=0]
----
<textField classNames="bordered"/>
----

Define the class in a loaded application stylesheet:

.my-project.css
[source,css,indent=0]
----
vaadin-text-field.bordered {
    --vaadin-input-field-background: white;
}
----

[[documented-selectors]]
[[stylable-parts]]
=== Stylable Parts of Components

Components expose several types of elements for styling.

[[root-elements]]
==== Root Elements

Each component has a root HTML element whose name usually starts with `vaadin-` or `jmix-`, for example `vaadin-button` or `jmix-value-picker`.

.my-project.css
[source,css,indent=0]
----
vaadin-button {
    background: gray;
}
----

[[shadow-parts]]
==== Shadow Parts

Shadow parts are elements inside the component shadow DOM. Use the `::part()` selector. For example, use the `input-field` part to change the input surface of a text field:

.my-project.css
[source,css,indent=0]
----
vaadin-text-field::part(input-field) {
    background: white;
    border: 1px solid black;
}
----

.Text field with a custom background and border
image::themes/styled-textfield.png[align="center", width="226"]

[[regular-child-elements]]
==== Child Elements

Normal HTML child elements are not in the shadow DOM. Use a child selector such as `>`:

.my-project.css
[source,css,indent=0]
----
.button-row > vaadin-button {
    flex: 1;
}
----

Some components also expose pseudo-elements and nested components. Use the selectors listed on the component reference page.

[[component-states]]
=== Component States

Components expose states such as disabled, read-only, invalid, and focused. Most states are available as attributes on the component root element.

.my-project.css
[source,css,indent=0]
----
vaadin-button[disabled] {
    background: lightgray;
    color: darkgray;
}
----

Combine a state selector with a part selector when necessary:

.my-project.css
[source,css,indent=0]
----
vaadin-text-field[readonly]::part(input-field) {
    border-color: gray;
}
----

Native states such as hover use CSS pseudo-classes:

.my-project.css
[source,css,indent=0]
----
vaadin-button:hover {
    border-color: blue;
}
----

[[styling-component-instances]]
=== Styling Component Instances

Combine a component selector with a CSS class to style one or more selected instances:

[source,xml,indent=0]
----
<textField classNames="bordered"/>
----

.my-project.css
[source,css,indent=0]
----
vaadin-text-field.bordered::part(input-field) {
    background: white;
    border: 1px solid black;
}
----

You can also scope rules to components inside a parent element with a custom class.

[[generating-styles-dynamically]]
== Changing Styles in Java

Use the component `Style` API for a value that is calculated by application logic:

[source,java,indent=0]
----
@ViewComponent
private JmixButton myBtn;

@Subscribe
public void onInit(final InitEvent event) {
    myBtn.getStyle().set("color", "white");
    myBtn.getStyle().set("background-color", "purple");
}
----

NOTE: Inline styles can change only the component root element. They cannot target parts or states.

For more control, define a custom CSS property in the application stylesheet and change its value from Java:

.my-project.css
[source,css,indent=0]
----
html {
    --my-button-text-color: darkblue;
}

vaadin-button.my-button {
    color: var(--my-button-text-color);
}
----

[source,java,indent=0]
----
UI.getCurrent().getElement().getStyle()
        .set("--my-button-text-color", "white");
----

This approach can affect component parts, states, and multiple components that use the same property.
