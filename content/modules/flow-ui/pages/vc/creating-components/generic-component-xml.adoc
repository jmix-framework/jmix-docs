Элемент XML `component` позволяет вам создать любой UI-компонент, указав его полное имя класса (FQN). Свойства компонента определяются с помощью вложенных элементов `property`, аналогично настройке действия.

Например, вы можете определить компонент `Button` таким образом:

[source,xml,indent=0]
----
include::example$/onboarding/src/main/resources/com/company/onboarding/view/customcomponent/genericcomponent/generic-component-view.xml[tags=button-component-xml]
----

Вот пример определения пользовательского компонента:

Фреймворк создает экземпляр класса компонента и применяет заданные свойства через соответствующие методы-сеттеры. В этом примере
свойство `text` соответствует `setText()`, а парсер свойства `ICON` преобразует `ARCHIVE` в экземпляр иконки для `setIcon()`.

Подписаться на универсальный компонент в контроллере экрана можно так же, как и на обычный декларативный компонент:

[source,java,indent=0]
----
@Autowired
protected Notifications notifications;

@Subscribe(id = "button", subject = "clickListener")
public void onButtonClick(ClickEvent<JmixButton> event) {
    notifications.show("Saved!");
}
----

Этот же механизм можно использовать и для пользовательского компонента, если его сеттеры принимают преобразованные значения:

[source,xml,indent=0]
----
include::example$/onboarding/src/main/resources/com/company/onboarding/view/customcomponent/genericcomponent/generic-component-view.xml[tags=test-component-xml]
----

В этом примере класс `TestComponent` определяет сеттеры для `stringsList`, `stringsSet`, `stringsArray`,
`strings` и `dataContainer`. Jmix преобразует строковые значения из XML и разрешает `productsDc`
контейнер данных перед вызовом соответствующих сеттеров.

[[property-configuration]]
== Конфигурация свойств

* Значение атрибута `name` преобразуется в имя метода-сеттера, например:

** `text` → `setText()`
** `dataLoader` → `setDataLoader()`

* Фреймворк ищет метод с соответствующим `name` и одним входным параметром для установки значения.
+
NOTE: Если несколько методов имеют одинаковое имя, нет гарантии, что для установки значения будет использован именно предполагаемый метод.

* Тип входного параметра найденного метода используется для преобразования строкового значения из атрибута `value` в фактическое значение.
+
Встроенное преобразование поддерживает `String`, `Class`, логические и числовые типы, перечисления, `List`, `Set` и массивы.
Сеттеры с varargs тоже работают, поскольку они обрабатываются как параметры-массивы. Элементы коллекций и массивов разделяются пробелами или запятыми перед преобразованием.

* Атрибут `type` указывает, что строковое значение должно быть преобразовано одним из подключаемых бинов `PropertyParser`:
+
[cols="1,1,3", options="header"]
|===
| Тип | Парсер | Описание

| `ICON`
| `IconPropertyParser`
| Преобразует строку в экземпляр `Icon`

| `CONTAINER_REF`
| `DataContainerPropertyParser`
| Находит контейнер данных по `ID`

| `LOADER_REF`
| `DataLoaderPropertyParser`
| Находит загрузчик данных по `ID`
|===

[[property-parsers]]
== Парсеры свойств

Когда строковые значения не могут быть напрямую преобразованы с использованием типа параметра, преобразованием занимаются подключаемые бины `PropertyParser`.

В настоящее время существует три реализации:

* *IconPropertyParser*. Преобразует строки в экземпляры `Icon`.
** Если переданная строка содержит разделитель `:`, новый `Icon` создается с использованием значений _коллекции иконок_ и _имени иконки_.
** В противном случае строка трактуется как имя константы `VaadinIcon`.
+
Примеры:
** `"PLUS"` → иконка `VaadinIcon.PLUS`.
** `"myicons:custom"` → Иконка из пользовательской коллекции `"myicons"` с именем `"custom"`.

* *DataContainerPropertyParser*. Возвращает xref:flow-ui:data/data-containers.adoc[контейнер данных] с заданным `ID` из объекта `ViewData` соответствующего экрана.

* *DataLoaderPropertyParser*. Возвращает xref:flow-ui:data/data-loaders.adoc[загрузчик данных] с заданным `ID` из объекта `ViewData` соответствующего экрана.
