[[dataset-constraints]]
== 数据集约束

Superset 中的仪表盘可以包含多个图表，显示来自不同数据集的数据。`SupersetDashboard` 组件可以对这些数据集设置约束。约束可以在组件的 XML 元素中静态定义，也可以在运行时动态计算。

如需使用约束，先定义数据集的 ID，再编写一个原生 SQL 条件，该条件将追加到数据集查询的 *WHERE* 子句中。

TIP: 无法直观地从 Superset UI 中找到数据集 ID。当从数据集列表打开数据集时，可以从地址栏显示的 URL 的 `datasource_id` 参数中获取。

[[static-dataset-constraints]]
=== 静态约束

考虑在 xref:superset:getting-started.adoc[superset 入门] 部分创建的 `Employees' salaries` 仪表盘中使用静态数据集约束。它使用的数据集加载员工、部门和薪资。假设需要限制薪资的下限，例如薪资 `80,000` 及以上员工。

约束在 `dashboard` 组件的 `datasetConstraint` 内部元素定义。可以在 Studio 中通过组件的 *Add* 操作添加，也可以在 XML 中手动添加。

[[dataset-constraints-provider]]
=== 约束 provider

数据集约束还可以在运行时动态计算，并在 Jmix 应用中打开仪表盘时传递给 Superset。通过这种方式可以根据当前用户权限或其他条件过滤仪表盘数据。

数据集约束由 `DatasetConstraint` Java 类表示。可以通过下列方式为 `SupersetDashboard` 组件提供约束列表：

* 在视图中创建 `datasetConstraintsProvider` 处理器并返回约束列表。

* 创建一个实现 `DatasetConstraintsProvider` 接口的 Spring bean，并使用 `setDatasetConstraintsProvider()` 方法将其传递给组件。

假设现在有一个需求：部门经理只能查看自己部门的薪资信息。数据集约束可以使用分配给当前用户的行级角色。

== 元素

一个 `dashboard` 可以包含 `datasetConstraints` 元素，其中包含零个或多个 `datasetConstraint` 元素。每个 `datasetConstraint` 需要一个 `datasetId` 属性，并将其中的文本内容作为 SQL 条件。请参见 <<static-dataset-constraints,静态数据集约束>>。
