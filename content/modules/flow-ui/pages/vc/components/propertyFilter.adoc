----
include::example$ui-samples/main/resources/io/jmix/uisamples/view/flowui/components/propertyfilter/editableoperation/property-filter-editable-operation.xml[tags=filtering-operations]

如果需要限制用户在一定范围内选择运算符，可以在 <<operationsList,operationsList>> 属性中配置支持的运算符名称，由逗号或空格分隔。在 Java 中，使用 `setOperationsList()` 做相同的配置。

组件会忽略即使在 `operationsList` 中配置了但实体属性类型不支持的运算符。因此，`operation` 属性指定的运算符必须支持实体属性的类型，如果同时也配置了 `operationsList`，则需要包含 `operation` 指定的运算符。否则会抛出异常。

[[date-interval]]
== 日期区间

++++
<div class="jmix-ui-live-demo-container">
    <a href="https://demo.jmix.io/ui-samples/sample/property-filter-date-interval-operation" class="live-demo-btn" target="_blank">在线示例</a>

组件提供了多个按日期区间过滤的选项。选择 `in interval` 运算符，并在对话框中输入区间值。

可选选项包括：

* *Last（之前）*：例如“过去 3 个月”或“过去 12 周”。
* *Next（之后）*：例如“未来 3 年”或“未来 48 小时”。
* *Predefined（预定义）*：快速选择，包括“今天”、“明天”、“本月”或“今年”。
* *Relative date and time（相对时间）*：用于类似“到当天结束时”、“在小时开始时”、“不是一年的最后一天”等条件。
* *Custom（自定义）*：任意开始日期和结束日期。开始日期包含在范围内，结束日期不包含。

[[programmatic-changes]]
== 编程式设置

当用户在 UI 中修改过滤器值或者运算符时，数据会自动重新加载。而编程式更改却有不同的行为：

* `setValue()` 更新条件但不重新加载数据
* 在单独的 `propertyFilter`（在视图中定义的独立组件带有自己的 `dataLoader`）调用 `setOperation()` 会立即重新加载数据。如果是修改 `groupFilter` 或 `genericFilter` 中的 `propertyFilter` 条件，则仅更新条件，不重新加载数据。

如需编程式配置过滤器，例如，需要在某个操作中修改过滤器的运算符和值，那么需要先修改运算符（修改运算符类型会重置当前值），再设置值，然后调用 `apply()`。这样数据才能按照正确的条件加载。
