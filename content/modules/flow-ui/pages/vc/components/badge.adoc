= badge

[.since]
Since Jmix 3.1

`badge` displays a small piece of information, such as a status, a count or a label.

[cols="1h,1", options="autowidth", grid=none, frame=none]
|===
|XML Element
|`badge`

|Java Class
|`Badge`
|===

[[basics]]
== Basics

++++
<div class="jmix-ui-live-demo-container">
    <a href="https://demo.jmix.io/ui-samples/sample/badge-simple" class="live-demo-btn" target="_blank">LIVE DEMO</a>

++++

The xref:vc/common-attributes.adoc#text[text] attribute sets the label of the badge. Keep it short: one or two words. The `success`, `warning` and `error` <<theme-variants,theme variants>> set the color of the badge. Without a variant, the badge uses the accent color of the theme.

[source,xml,indent=0]
----
include::example$ui-samples/main/resources/io/jmix/uisamples/view/flowui/components/badge/simple/badge-simple.xml[tags=basics]
----

image::visual-components/components/badge-basics.png["Badges with the default and success, warning and error colors", align="center", width="322"]

Badges look like buttons, but they are not interactive. Do not use verbs in badge labels, and do not place badges next to buttons of a similar color.

[[data-binding]]
== Data-aware `badge`

++++
<div class="jmix-ui-live-demo-container">
    <a href="https://demo.jmix.io/ui-samples/sample/badge-dataaware" class="live-demo-btn" target="_blank">LIVE DEMO</a>
</div>
++++

A badge can show the value of an entity attribute. Bind it to a xref:data/data-containers.adoc[data container] using the xref:vc/common-attributes.adoc#dataContainer[dataContainer] and xref:vc/common-attributes.adoc#property[property] attributes:

[source,xml,indent=0]
----
include::example$ui-samples/main/resources/io/jmix/uisamples/view/flowui/components/badge/dataaware/badge-dataaware.xml[tags=data-binding]
----

The binding is read-only. The badge shows the attribute value as text and updates it when the value changes. The value is formatted according to its datatype. For example, an enumeration value is shown as its localized caption, and a `null` value is shown as an empty badge.

If the current user has no permission to view the attribute, the badge is hidden.

Use icons only when they make the badge easier to understand. Too many icons make the view harder to read.

The `icon-only` variant shows only the icon. Set the text anyway. It is hidden on the screen, but screen readers announce it.

[source,xml,indent=0]
----
include::example$ui-samples/main/resources/io/jmix/uisamples/view/flowui/components/badge/icons/badge-icons.xml[tags=icon-only]
----

Use icon-only badges for icons that all users understand, such as a check mark for "yes", and for content that repeats, for example, in lists and tables.

[[numbers]]
== Number

++++
<div class="jmix-ui-live-demo-container">
    <a href="https://demo.jmix.io/ui-samples/sample/badge-theme-variant" class="live-demo-btn" target="_blank">LIVE DEMO</a>
</div>
++++

The <<number,number>> attribute shows a number in the badge, for example, the number of unread messages. If the badge has both text and a number, it shows both.

The `number-only` variant shows only the number. As with `icon-only`, set the text for screen readers:

[source,xml,indent=0]
----
include::example$ui-samples/main/resources/io/jmix/uisamples/view/flowui/components/badge/themevariant/badge-theme-variant.xml[tags=number-only]
----

In the view controller, use the `setNumber()` method to change the number and `setNumber(null)` to remove it.

Screen readers read only the content of the badge. A number alone can confuse users, so set a text that says what is counted. If the number changes while the view is open, set <<ariaRole,ariaRole>> to `status`, and screen readers will announce the new value.

[[theme-variants]]
== Theme Variants

++++
<div class="jmix-ui-live-demo-container">
    <a href="https://demo.jmix.io/ui-samples/sample/badge-theme-variant" class="live-demo-btn" target="_blank">LIVE DEMO</a>
</div>
++++

Use the xref:vc/common-attributes.adoc#themeNames[themeNames] attribute to apply variants. You can combine several variants, for example, `themeNames="success filled"`. In the view controller, use the `addThemeVariants()` method with the `BadgeVariant` enumeration.

image::visual-components/components/badge-visual-variants.png["Badges with the filled, icon-only, number-only and dot variants", align="center", width="191"]

[cols="1,4,1", options="header"]
|===
|Variant
|Description
|Supported By

|`success`, `warning`, `error`
|Applies a semantic color.
|Aura, Lumo

|`contrast`
|Applies a neutral high-contrast color.
|Lumo

|`filled`
|Uses a solid background instead of a tinted one to draw more attention. Can be combined with all other variants.
|Aura, Lumo

|`small`
|Makes the badge smaller.
|Aura, Lumo

|`icon-only`
|Shows only the icon. See <<icons>>.
|Aura, Lumo

|`number-only`
|Shows only the number. See <<numbers>>.
|Aura, Lumo

|`dot`
|Shows the badge as a small dot and hides all its content.
|Aura, Lumo
|===

[[attributes]]
== Attributes

xref:vc/common-attributes.adoc[Common attributes] serve the same purpose for all components.
The following attributes are specific to `badge`:

[cols="2,5,1", options="header"]
|===
|Name
|Description
|Default

|[[ariaRole]]`ariaRole`
|Sets the ARIA role of the badge, which screen readers use. For example, `status` makes screen readers announce changes of the badge content. See <<numbers>>.
|—

|[[icon]]`icon`
|Sets the icon displayed before the text. See <<icons>>.
|—

|[[number]]`number`
|Sets the number displayed in the badge. See <<numbers>>.
|—

|[[themeNames]]`themeNames`
|Applies one or more variants listed in <<theme-variants>>.
|—
|===
