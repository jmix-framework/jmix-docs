= genericFilter
:page-aliases: vcl/components/filter.adoc

Компонент `genericFilter` формирует настраиваемые условия для загрузчика данных и отображает их в виде интерактивного фильтра. По умолчанию `genericFilter` добавляется на стандартные экраны сущностей, например на xref:flow-ui:views/view-classes.adoc#standard-list-view[экраны списка].

[[runtime-usage]]
== Использование во время выполнения

В зависимости от конфигурации фильтра и <<permissions,предоставленных разрешений>> пользователи могут:

* [[quick-filter-example]]Создавать временный фильтр, который действует, пока открыт текущий экран. Пользователи могут вводить значения условий, изменять доступные операции и сбрасывать фильтр.
* [[adding-conditions]][[condition-types]]Применять сохранённые фильтры и конфигурации, доступные в приложении. Пользователи не могут редактировать или удалять их, но могут копировать при наличии разрешения `ui.genericfilter.modifyConfiguration`.
* [[creating-conditions]]Создавать новые условия с помощью мастеров. Эти условия эквивалентны тем, которые создают разработчики:
** <<property-conditions,*Условие по атрибуту*>> – фильтрует по атрибуту сущности.
** <<jpql-conditions,*Условие JPQL*>> – фильтрует по пользовательскому запросу.
** <<group-conditions,*Групповое условие*>> – объединяет несколько условий с помощью `AND` или `OR`.
** xref:search:search-in-ui.adoc#fts-condition-in-filter-component[*Условие полнотекстового поиска*] – выполняет поиск по настроенным атрибутам сущности. Доступно при установленном модуле xref:search:index.adoc[Search].
* [[runtime-configuration]][[run-time-configuration]]Сохранять, редактировать, копировать и удалять персональные конфигурации времени выполнения при наличии разрешения `ui.genericfilter.modifyConfiguration`.
* [[avaialable-for-all-users]]Делать конфигурацию времени выполнения доступной для всех пользователей или назначать её конфигурацией по умолчанию при наличии разрешения `ui.genericfilter.modifyGlobalConfiguration`.

[NOTE]
====
Загрузчик данных может иметь собственное _базовое условие_, заданное в элементе `condition` загрузчика или программно с помощью `DataLoader.setCondition()`. `genericFilter` не заменяет его: условие активной конфигурации объединяется с базовым условием оператором `AND`, в том числе при переключении между конфигурациями.

== Условия свойства

`propertyFilter` преобразует атрибут сущности и операцию сравнения в условие загрузчика данных. Атрибут `property` принимает прямой или вложенный путь к атрибуту, а компонент создаёт поле значения в соответствии с метаданными атрибута.

В XML в конфигурацию, заданную на этапе разработки, добавляются фильтры для `customer` и `customer.grade`. Оба используют операцию `EQUAL` и атрибут `operationEditable="true"`: сначала отображается операция *Равно*, но пользователь может изменить её на запущенном экране.

В примере Java эквивалентная конфигурация создаётся с помощью низкоуровневого API. Каждый `PropertyFilter` связывается с загрузчиком данных `genericFilter`, получает сгенерированное имя параметра и компонент значения, а также делегирует изменение условия. Затем фильтры добавляются в корневой логический компонент конфигурации.

[[jpql-conditions]]
== Условия JPQL

++++
<div class="jmix-ui-live-demo-container">
    <a href="https://demo.jmix.ru/ui-samples/sample/generic-filter-jpql-condition" class="live-demo-btn" target="_blank">ДЕМО</a>
</div>
++++

`jpqlFilter` задаёт произвольный предикат JPQL для условий, которые нельзя выразить сравнением атрибутов. В примере заказы фильтруются по товару из коллекции `items`: предложение `join` вводит псевдоним коллекции, а `where` сравнивает идентификатор товара с параметром фильтра.

В XML-примере объявляется пространство имён JPQL-условия, классом параметра назначается `Product`, а предложения `join` и `where` помещаются внутрь `condition`. Во время выполнения класс параметра определяет тип компонента значения, отображаемого для условия.

В Java-примере такой же фильтр создаётся через низкоуровневый API. Предложения `where` и `join` передаются в `setCondition()`, задаются класс и подпись параметра, создаются имя параметра и совместимый компонент значения, после чего фильтр добавляется в программно созданную конфигурацию этапа разработки.

При определении JPQL-условия используйте следующий синтаксис:

* Начните необязательное выражение `join` с `join` или `left join` и используйте `\{E}` вместо псевдонима сущности загрузчика данных.
* В `where` используйте `\{E}` для псевдонима сущности и `?` для значения, предоставленного фильтром. Условие может содержать только один параметр `?`, но также может содержать параметры xref:data-access:jpql-extensions.adoc#session-and-user-attributes[атрибут сеанса и пользователя].
* Для параметра со значением коллекции, используемого в выражении `IN`, включите свойство `hasInExpression` фильтра.

[[group-conditions]]
== Условия группы

++++
<div class="jmix-ui-live-demo-container">
    <a href="https://demo.jmix.ru/ui-samples/sample/generic-filter-group-condition" class="live-demo-btn" target="_blank">ДЕМО</a>
</div>
++++

`groupFilter` объединяет вложенные компоненты фильтра с `AND` или `OR`. Группы могут быть вложенными, а корневой логический компонент конфигурации объединяет своих прямых дочерних элементов со своей собственной операцией.

В XML-примере создаётся группа `OR` с фильтрами по атрибутам `active` и `grade`. Фильтр `age` находится вне этой группы, поэтому корневая операция по умолчанию формирует следующее выражение:

----
(active = false OR grade = STANDARD) AND age >= 30
----

В примере Java явно создаётся такое же дерево условий. Код создаёт групповой фильтр и фильтры по атрибутам, добавляет фильтры по атрибутам в группу, а затем помещает группу и фильтр `age` в корень конфигурации. Для каждого компонента задаются текущее и сохранённое значения, поэтому при выборе конфигурации восстанавливаются те же значения.

Для каждой конфигурации задайте атрибут `id` с уникальным в пределах этого `genericFilter` значением. Если атрибут `name` не указан, `id` используется как ключ в xref:localization:message-bundles.adoc[пакете сообщений]. Конфигурация по умолчанию задаётся атрибутом `default`.

[[creating-filter-programmatically]]
== Создание фильтра программно

Создавать и настраивать `genericFilter` в Java можно с помощью fluent API билдеров с двумя точками входа:

* `filterComponentBuilder()` создаёт компоненты фильтра — `propertyFilter`, `jpqlFilter` и `groupFilter`.
* `runtimeConfigurationBuilder()` собирает `RunTimeConfiguration` из этих компонентов и регистрирует его в фильтре.

Билдер выполняет всю необходимую инициализацию внутри (делегирование модификации условий, генерацию имени параметра и компонента значения), поэтому программно созданный компонент ведёт себя точно так же, как объявленный в XML. У владеющего им `genericFilter` должен быть `DataLoader`, иначе методы билдера выбрасывают `IllegalStateException`.

CAUTION: В настоящее время fluent API билдеров является экспериментальным и может измениться в будущих версиях Jmix.

Следующий пример создаёт `genericFilter`, строит условие по свойству и регистрирует конфигурацию:

[source,java,indent=0]
----
include::example$/onboarding/src/main/java/com/company/onboarding/view/component/genericfilter/GenericFilterView.java[tags=UiComponents;vbox;CollectionLoader;programmaticFilter]
----

<1> Создаёт `genericFilter` с помощью фабрики `uiComponents`.
<2> Помещает `genericFilter` на экран внутрь контейнера `vbox`, объявленного в дескрипторе экрана и инжектированного в контроллер.
<3> Строит `PropertyFilter` с помощью `filterComponentBuilder()`.
<4> Регистрирует конфигурацию времени выполнения с помощью `runtimeConfigurationBuilder()` и добавляет в неё фильтр.
<5> Немедленно активирует конфигурацию. Это не постоянный маркер конфигурации по умолчанию, он просто делает конфигурацию текущей.
<6> Строит и регистрирует конфигурацию. Каждый экземпляр билдера одноразовый.

=== Создание конфигурации времени выполнения

`runtimeConfigurationBuilder()` создаёт `RunTimeConfiguration` и регистрирует его в фильтре.

[source,java,indent=0]
----

<1> Добавляет компонент с типизированным значением по умолчанию; тип значения проверяется во время компиляции. Используйте `add(component)` без значения по умолчанию или `addAll(components...)`, чтобы добавить несколько сразу.
<2> Добавляет группу, построенную выше.
<3> Немедленно активирует конфигурацию. Это не постоянный маркер конфигурации по умолчанию.
<4> Позволяет пользователю удалить эту конфигурацию. По умолчанию конфигурации, созданные с помощью билдера, защищены от удаления пользователем.

* Каждый экземпляр билдера одноразовый — повторный вызов `build()` или `buildAndRegister()` выбрасывает `IllegalStateException`.
* `id` конфигурации должен быть уникальным в пределах фильтра.
* У владеющего ею `genericFilter` должен быть `DataLoader`.

NOTE: Билдер создаёт `RunTimeConfiguration`. Билдера для `DesignTimeConfiguration` не существует. Чтобы создавать конфигурации программно на более низком уровне, используйте `addConfiguration(id, name)` (который возвращает `DesignTimeConfiguration`) и создавайте и добавляйте компоненты фильтра напрямую, либо постройте `RunTimeConfiguration` и зарегистрируйте её с помощью `addConfiguration(configuration)`. Это более низкоуровневый подход, который заменяет API билдеров.

[[permissions]]
== Разрешения

Чтобы пользователи могли настраивать фильтр, предоставьте следующие специальные разрешения:

* `ui.genericfilter.modifyConfiguration` позволяет пользователям создавать, редактировать и удалять собственные конфигурации времени выполнения.
* `ui.genericfilter.modifyGlobalConfiguration` позволяет пользователям создавать, редактировать и удалять конфигурации, доступные всем пользователям.
* `ui.genericfilter.modifyJpqlCondition` позволяет пользователям создавать и изменять условия JPQL во время выполнения.

== Элементы

`genericFilter` может содержать элементы `actions`, `conditions`, `configurations`, `properties`, `responsiveSteps` и xref:vc/components/tooltip.adoc[tooltip]. В следующих подразделах описаны элементы конфигурации, относящиеся к фильтру.

[[actions-element]]
=== actions

Определяет список действий для управления фильтром. По умолчанию в меню image:flow-ui:visual-components/components/generic-filter-settings-button.png[align="center", width="42"] *Настройки фильтра* доступны следующие действия:

* *Сохранить* — сохраняет изменения в текущей конфигурации. Реализовано `FilterSaveAction` (`type="genericFilter_save"` в XML).
* *Сохранить со значениями* — сохраняет изменения в текущей конфигурации вместе со значениями в полях условий [<<condition-field, 5>>] в качестве значений по умолчанию.
* *Сохранить как* — сохраняет текущую конфигурацию под другим именем. Реализовано `FilterSaveAsAction` (`type="genericFilter_saveAs"` в XML).
* *Редактировать* — открывает редактор текущей <<runtime-configuration,конфигурации времени выполнения>>. Недоступно для <<design-time-configuration,конфигураций времени разработки>>. Реализовано классом `FilterEditAction` (`type="genericFilter_edit"` в XML).
* *Удалить* — удаляет текущую <<runtime-configuration,конфигурацию времени выполнения>>. Недоступно для <<design-time-configuration,конфигураций времени разработки>>. Реализовано классом `FilterRemoveAction` (`type="genericFilter_remove"` в XML).
* *Копировать* — создаёт копию текущей <<runtime-configuration,конфигурации времени выполнения>>. Реализовано классом `FilterCopyAction` (`type="genericFilter_copy"` в XML).
* *Очистить значения* — очищает значения в полях условий [<<condition-field,5>>]. Реализовано классом `FilterClearValuesAction` (`type="genericFilter_clearValues"` в XML).
* *Добавить* — добавляет условие в текущую конфигурацию. Реализовано `FilterAddConditionAction` (`type="genericFilter_addCondition"` в XML).
* *Сбросить* — возвращает компонент к пустому быстрому фильтру. Реализовано классом `FilterResetAction` (`type="genericFilter_reset"` в XML).

[[properties-element]]
=== properties

Определяет, какие атрибуты сущности можно добавлять в условие. Этот элемент имеет следующие атрибуты:

* `include` - указывает регулярное выражение. Атрибуты сущности, соответствующие этому выражению, включаются.
* `exclude` - указывает регулярное выражение. Атрибуты сущности, соответствующие этому выражению, исключаются.
* `excludeProperties` - указывает разделённый запятыми список имён атрибутов или путей к ним, которые следует исключить. Например: `customer.name`.
* `excludeRecursively` - определяет, должен ли атрибут из `excludeProperties` быть рекурсивно исключён для всего графа сущностей. Если указано `true`, дочерние атрибуты исключённого атрибута также исключаются.

Пример:

Следующие атрибуты сущности игнорируются:

* Недоступные из-за разрешений безопасности
* Неперсистентные атрибуты
* Атрибуты, аннотированные `@SystemLevel`
* Атрибуты типа `byte[]`
