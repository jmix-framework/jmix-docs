= genericFilter 通用过滤器
:page-aliases: vcl/components/filter.adoc

`genericFilter` 组件为数据加载器构建可配置的条件，并以交互式的组件形式展示。默认添加在标准实体视图中，例如，xref:flow-ui:views/view-classes.adoc#standard-list-view[列表视图]。

|===
|XML 元素

过滤器组件包含：

. [[refresh-button]] 带下拉框的 *Refresh（刷新）* 按钮 
. [[operator-selector]] 比较操作符选择器。
. [[filter-settings-button]] *Filter Settings（过滤器设置）* 按钮。
. [[refresh-drop-down-menu]] 保存的过滤器和配置列表。
. [[condition-field]] 条件的值字段。
. [[add-condition-link]] *Add search condition（添加搜索条件）* 链接按钮。

[[runtime-usage]]
== 运行时使用

依据过滤器配置和 <<permissions,授予的权限>>，支持下列用户操作：

* [[quick-filter-example]]创建一个临时过滤器，在当前视图打开期间有效。用户可以输入条件值、改变条件运算符或重置过滤器。
* [[adding-conditions]][[condition-types]]使用应用程序提供的已保存过滤器和配置。用户不能编辑或移除，但在被授予 `ui.genericfilter.modifyConfiguration` 时可以进行复制。
* [[creating-conditions]]使用向导创建新过滤条件：
** <<property-conditions,*属性条件*>> – 按实体属性过滤。
** <<jpql-conditions,*JPQL 条件*>> – 使用自定义查询语句过滤。
** <<group-conditions,*分组条件*>> – 使用 `AND` 或 `OR` 组合多个条件。
** xref:search:search-in-ui.adoc#fts-condition-in-filter-component[*全文搜索条件*] – 在配置的实体属性中搜索。安装了 xref:search:index.adoc[搜索] 扩展组件时可用。
* [[runtime-configuration]][[run-time-configuration]]用户有 `ui.genericfilter.modifyConfiguration` 角色时，保存、编辑、复制和移除个人运行时配置。
* [[avaialable-for-all-users]]用户有 `ui.genericfilter.modifyGlobalConfiguration` 角色时，能将运行时配置开放给所有用户或设为默认配置。

[[jpql-conditions]]
== JPQL 条件

++++
<div class="jmix-ui-live-demo-container">
    <a href="https://demo.jmix.io/ui-samples/sample/generic-filter-jpql-condition" class="live-demo-btn" target="_blank">在线示例</a>

使用 `jpqlFilter` 可以自定义 JPQL 谓词，当条件无法表示为属性值比较时使用。示例中，需要按 `items` 集合中的产品过滤订单：`join` 子句引入集合别名，`where` 子句将产品标识符与过滤器参数进行比较。

XML 示例声明 JPQL 条件命名空间，将 `Product` 设置为参数类，并在 `condition` 内嵌套 `join` 和 `where` 子句。运行时，参数类型决定条件显示的值组件类型。

Java 示例通过底层 API 创建相同的过滤器。将 `where` 和 `join` 子句传递给 `setCondition()`，分配参数类和标签，生成参数名和兼容的值组件，并将过滤器添加到以编程方式创建的设计时配置中。

定义 JPQL 条件时使用以下语法：

* 可选的 `join` 子句（以 `join` 或 `left join` 开始），并使用 `\{E}` 表示实体别名。
* 在 `where` 子句中，使用 `\{E}` 表示实体别名，使用 `?` 表示过滤器提供的值。一个条件只能包含一个 `?` 参数，还可以使用 xref:data-access:jpql-extensions.adoc#session-and-user-attributes[会话和用户属性] 参数。
* 对于在 `IN` 表达式中使用的集合值参数，需启用过滤器的 `hasInExpression` 属性。

[[creating-filter-programmatically]]
== 编程式创建过滤器

可以使用 builder 的流式 API 在 Java 中创建和配置 `genericFilter`，该 API 有两个入口点：

* `filterComponentBuilder()` 创建过滤组件 – `propertyFilter`、`jpqlFilter` 和 `groupFilter`。
* `runtimeConfigurationBuilder()` 用这些组件组装一个 `RunTimeConfiguration`，并将其注册到过滤器中。

Builder 会在内部执行所有必需的初始化（条件修改代理、参数名称和生成值组件），因此以编程方式构建的组件与在 XML 中声明的组件行为完全一致。父 `genericFilter` 必须有一个 `DataLoader`；否则 builder 的方法会抛出 `IllegalStateException`。

CAUTION: Builder API 目前为实验性功能，可能在未来的 Jmix 版本中发生变化。

以下示例创建了一个 `genericFilter`，构建了一个属性条件，并注册了一个配置：

[source,java,indent=0]
----
include::example$/onboarding/src/main/java/com/company/onboarding/view/component/genericfilter/GenericFilterView.java[tags=UiComponents;vbox;CollectionLoader;programmaticFilter]
----

<1> 用 `uiComponents` 工厂创建 `genericFilter`。
<2> 将 `genericFilter` 放入视图中声明的 `vbox` 内。
<3> 使用 `filterComponentBuilder()` 构建一个 `PropertyFilter`。
<4> 使用 `runtimeConfigurationBuilder()` 注册一个运行时配置，并添加过滤器。
<5> 立即激活该配置。这里并不是将配置持久化为默认配置，而只是将配置设为当前配置。

[[permissions]]
== 权限

为用户分配以下特定权限可以允许用户配置过滤器：

* `ui.genericfilter.modifyConfiguration` 允许用户创建、编辑和移除自己的运行时配置。
* `ui.genericfilter.modifyGlobalConfiguration` 允许用户创建、编辑和移除对所有用户可用的配置。
* `ui.genericfilter.modifyJpqlCondition` 允许用户在运行时创建和更改 JPQL 条件。

== XML 内部元素

一个 `genericFilter` 可以包含 `actions`、`conditions`、`configurations`、`properties`、`responsiveSteps` 和 xref:vc/components/tooltip.adoc[tooltip] 作为其内部元素。下面是过滤器特定内部元素的介绍。

[[actions-element]]
=== actions

定义过滤器管理的操作列表。框架在 *Filter Settings（过滤器设置）* image:flow-ui:visual-components/components/generic-filter-settings-button.png[align="center", width="42"] 中提供下列默认操作：

* *Save（保存）* -- 保存当前对过滤器配置的修改。由 `FilterSaveAction` 实现（XML 中 `type="genericFilter_save"`）。
* *Save with values（带值保存）* -- 保存当前对过滤器配置的修改。，且使用条件字段 [<<condition-field, 5>>] 中的值作为过滤器的默认值。
* *Save as（另存为）* -- 将当前过滤器配置另存为新名称。由 `FilterSaveAsAction` 实现（XML 中 `type="genericFilter_saveAs"`）。
* *Edit（编辑）* -- 打开当前 <<runtime-configuration,运行时配置>> 的编辑器。对 <<design-time-configuration,设计时配置>> 禁用。由 `FilterEditAction` 实现（XML 中 `type="genericFilter_edit"`）。
* *Remove（移除）* -- removes the current <<runtime-configuration,运行时配置>>. 对 <<design-time-configuration,设计时配置>> 禁用。由 `FilterRemoveAction` 实现（XML 中 `type="genericFilter_remove"`）。
* *Copy（复制）* -- 复制当前的 <<runtime-configuration,运行时配置>>。由 `FilterCopyAction` 实现（XML 中 `type="genericFilter_copy"`）。
* *Clear values（清空值）* -- 清空过滤器条件值 [<<condition-field, 5>>]。由 `FilterClearValuesAction` 实现（XML 中 `type="genericFilter_clearValues"`）。
* *Add（添加）* -- 为当前的配置添加一个条件。由 `FilterAddConditionAction` 实现（XML 中 `type="genericFilter_addCondition"`）。
* *Reset（重置）* -- 将组件重置回空的快速过滤器。由 `FilterResetAction` 实现（XML 中 `type="genericFilter_reset"`）。

[[properties-element]]
=== properties

定义哪些实体属性可以用于过滤条件。该元素有下列属性：

* `include` -- 设置一个正则表达式，该表达式匹配的实体属性将被包含在可选属性中。
* `exclude` -- 设置一个正则表达式，该表达式匹配的实体属性将被排除在可选属性之外。
* `excludeProperties` -- 设置一个英文逗号分隔的应该被排除掉的属性或属性路径列表。示例：`customer.name`。
* `excludeRecursively` -- 设置 `excludeProperties` 里面定义的属性是否需要在对象图中递归地排除掉。如果设置的 true，那么属性和它的子属性都会被排除掉。
