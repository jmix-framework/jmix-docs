= 打开视图
:page-aliases: opening-screens.adoc

一个常规视图（非主视图）可以通过两种方式打开：通过 URL（在 `@Route` 注解指定）导航打开；在当前页面通过对话框形式打开。

使用导航方式时，浏览器的 URL 会根据应用程序 UI 的状态展示不同的 URL，并支持 _深度链接_。应用程序的用户可以复制特定视图和内容的 URL 并分享，例如，展示某个实体详情的 URL。

导航方式的缺点就是打开指定视图的传参相对复杂。只能以 https://vaadin.com/docs/v25/routing/route-parameters[路由^] 或 https://vaadin.com/docs/v25/routing/additional-guides/query-parameters[查询^] 参数的形式在 URL 中拼接。此外，关闭视图时，也没有办法给调用端返回任何信息。

当通过对话框窗口的形式打开视图时，浏览器 URL 不会有变化，但是调用方代码可以访问打开的视图实例。因此，可以支持给视图实例传递参数或者在关闭视图时返回一些结果值。例如，在选择控件中打开列表视图选择并返回实体实例时就使用了这种方式。

主菜单通过导航的方式打开视图。标准操作 xref:actions/list-actions.adoc#list_create[list_create]、xref:actions/list-actions.adoc#list_edit[list_edit] 和 xref:actions/list-actions.adoc#list_read[list_read] 也是通过导航方式打开详情视图，但是可以配置使用对话框方式打开。The xref:actions/entity-picker-actions.adoc#entity_lookup[entity_lookup] 标准操作始终使用对话框的方式打开列表视图，以便能返回选中的实体。xref:actions/entity-picker-actions.adoc#entity_read[entity_read] 操作也始终使用对话框。

下面我们介绍如何在应用程序代码中以编程的方式打开视图。

[[dialog-parameters]]
=== 设置弹窗参数

用几种方式可以设置打开的弹窗参数，包括尺寸：

. *使用 `@DialogMode` 注解*
+
在需要以弹窗方式打开的视图类上添加 `@DialogMode` 注解。这里可以设置视图弹窗的默认大小、是否模态窗以及其他弹窗参数。
+
[source,java,indent=0]
----
@ViewController("MyOnboardingView")
@ViewDescriptor("my-onboarding-view.xml")
@DialogMode(width = "50em", height = "40em", modality = DialogModalityMode.STRICT)
public class MyOnboardingView extends StandardView {
    // some code
}
----
+
使用 `modality` 属性控制对话框与 UI 其余部分的交互方式。可选值包括：
+
* `STRICT` - 显示模态遮罩，将焦点限制在对话框内，阻止鼠标指针事件，并阻止后台请求。
* `VISUAL` - 行为与 `STRICT` 相同，但不阻止后台请求。
* `MODELESS` - 不使用模态：无模态遮罩、无焦点限制、无后台阻止。
* `DEFAULT` - 兼容模式，保留已弃用的 `DialogMode.modal()` 属性配置的行为。

. *在打开的视图内部设置大小*
+
可以在视图控制器中修改视图弹窗的大小。有助于依赖运行时条件动态调整弹窗的大小，例如需要展示或隐藏某些页面组件。
+
[source,java,indent=0]
----

----
+
TIP: 如果当前视图不是以对话框形式打开的，则 `findDialog()` 方法返回 `null`。因此需要检查对话框实例是否为 `null`。
. *打开弹窗时设置大小*

[[maximizing-dialog-windows]]
=== 对话框窗口的最大化显示和还原

在 `DialogWindow` 中打开的视图可以最大化以填满视口，并可以还原到之前的大小和位置。默认情况下，最大化按钮是隐藏的。在 `@DialogMode` 中设置 `maximizable = true`，即可在对话框顶部关闭按钮旁边显示该按钮：

[source,java,indent=0]
----
include::example$/onboarding/src/main/java/com/company/onboarding/view/myonboarding/MyOnboardingView.java[tags=maximizable-dialog]
----

点击该按钮会最大化对话框。再次点击会还原对话框为最大化之前通过拖动或调整大小设置的尺寸和位置。

如需以编程方式配置该行为，请使用 `setMaximizable(boolean)`。`setMaximized(true)` 最大化对话框，而 `setMaximized(false)` 还原。这些方法在 `AbstractDialogWindow`（`DialogWindow` 的基类）上可用。`isMaximizable()` 和 `isMaximized()` 方法返回相应的设置。

以下示例打开一个最大化的对话框，并在更改状态之前注册监听器：

[source,java,indent=0]
----
include::example$/onboarding/src/main/java/com/company/onboarding/view/sample/SampleView.java[tags=dialogWindows;openMaximizedDialog]
----

`MaximizedChangeEvent` 的 `isMaximized()` 方法提供当前状态。当用户点击顶部按钮时，事件的 `isFromClient()` 方法返回 `true`；当状态以编程方式更改时，返回 `false`。使用 `getSource()` 可获取对话框窗口对象，使用 `getView()` 获取视图。

对话框最大化时，会禁用拖动和调整大小的功能。如果在此时调用 `setDraggable()` 和 `setResizable()`，这些设置会在对话框还原后生效。相应的 getter 返回这些配置的设置。

Aura 和 Lumo 主题支持以下用于 CSS 自定义属性：

* `--jmix-dialog-maximized-position`
* `--jmix-dialog-maximized-inset`
* `--jmix-dialog-maximized-width`
* `--jmix-dialog-maximized-height`

当对话框元素有 `jmix-maximized` 属性（即，最大化后）时，这些样式会生效。

[[detail-window-builder-options]]
=== 其他构建方法

`DetailWindowBuilder` 和 `DetailWindowClassBuilder` 提供了额外的方法，可将打开的详情视图与调用视图集成：

[cols="1,3",options="header"]
|===
|方法
|描述

|`withInitializer()`
|在详情视图打开之前初始化一个新的实体实例。初始化器仅在创建模式下被调用，即在 `newEntity()` 或 `newEntity(entity)` 之后。

|`withContainer()`
|指定在详情视图以 `SAVE` 关闭后需要更新的 `CollectionContainer`。如果该容器是嵌套的（如 xref:data/property-containers.adoc[属性容器] 中所述），框架还会为新的子实体初始化父实体引用，并为组合编辑配置父子 `DataContext` 关系。

|`withListDataComponent()`
|指定一个 `ListDataComponent`，例如 `DataGrid`，当没有通过 `withContainer()` 显式提供数据容器时，框架将从该组件获取绑定的集合容器。对话框关闭后，该组件也会获得焦点。

|`withParentDataContext()`
|为打开的详情视图设置父 `DataContext`。此时，详情视图会将更改保存到父数据上下文，而不是直接保存到数据存储。当子实体必须与主实体一起保存时，请使用此方法。有关信息，请参阅 xref:data/data-context.adoc#parent-data-context[父数据上下文]。

|`withTransformation()`
|将保存的实体写回字段、容器或列表数据组件之前对其进行特定的转换。

|`withField()`
|设置一个字段组件，该组件在详情视图以 `SAVE` 关闭后接收保存的实体。

|`withAddFirst()`
|当使用独立的集合容器时，定义新实体是否应添加到集合容器的开头位置。对于嵌套容器，新实体始终添加到末尾。

|`withViewConfigurer()`
|支持在对话框显示之前配置打开的视图实例。
|===

这些构建器方法通常在为子实体打开详情对话框时使用。

使用 `withListDataComponent()` 或 `withContainer()` 将对话框与当前视图中显示的集合进行关联，使用 `withParentDataContext()` 将编辑后的子实体合并到父视图数据上下文中。

具体设置取决于视图数据模型和实体关系配置。完整示例请参考 xref:data-modeling-composition-guide:index.adoc[组合指南]。有关父子数据上下文的更多信息，请参考 xref:data/data-context.adoc#parent-data-context[父数据上下文]。其他示例可在 https://demo.jmix.io/ui-samples[UI 示例^] 中找到。

[[view-inference-conventions]]
== 视图推断约定

框架支持从实体类推断列表、详情或只读视图。

当使用 `viewNavigators.listView(this, SomeEntity.class)` 方法导航至列表视图时，框架会按照下列顺序选择视图类：

. 视图使用了注解 `@PrimaryLookupView(SomeEntity.class)`。
. 视图的 id 为 `SomeEntity.list`。

当使用 `dialogWindows.lookup(this, SomeEntity.class)` 方法打开一个列表视图用于查找时，框架会按照下列顺序选择视图类：

. 视图使用了注解 `@PrimaryLookupView(SomeEntity.class)`。
. 视图的 id 为 `SomeEntity.lookup`。
. 视图使用了注解 `@PrimaryListView(SomeEntity.class)`。
. 视图的 id 为 `SomeEntity.list`。

当导航至一个详情视图，或者在对话框打开详情视图时，框架会按照下列顺序选择视图类：

. 视图使用了注解 `@PrimaryDetailView(SomeEntity.class)`。
. 视图的 id 为 `SomeEntity.detail`。

当导航至一个只读视图，或者在对话框打开只读视图时，框架会按照下列顺序选择视图类：

. 视图使用了注解 `@PrimaryReadView(SomeEntity.class)`。
. 视图的 id 为 `SomeEntity.read`。
. 视图使用了注解 `@PrimaryDetailView(SomeEntity.class)`。
. 视图的 id 为 `SomeEntity.detail`。

如果框架选中了一个详情视图，则会以只读模式打开。
