= Dashboard Component

The `dashboard` component shows content in a grid of widgets. The grid changes the number of columns to fit the available width. A widget can span several columns and rows, and widgets can be grouped into sections that users can collapse. In the editable mode, users move, resize, and remove widgets themselves.

[[widgets]]
== Widgets

A widget is declared by the `dashboardWidget` element. It requires an `id` and contains one component in the nested `content` element. The `title` attribute sets the text shown in the widget header and accepts a message key:

[source,xml,indent=0]
----
include::example$/vaadin-dashboard-ex1/src/main/resources/com/company/vaadindashboardex1/view/widgets/dashboard-widgets-view.xml[tags=content]
----

The `content` element accepts any component available in the view. To show several components in one widget, put them into a layout, as in the example above.

[[widget-header]]
=== Widget Header

Besides the title, a widget can have the `headerContent` element. Its component is shown in the widget header. Use it for a refresh button, a filter, or a status badge:

[source,xml,indent=0]
----
include::example$/vaadin-dashboard-ex1/src/main/resources/com/company/vaadindashboardex1/view/widgets/dashboard-widgets-view.xml[tags=header-content]

Both `content` and `headerContent` must contain exactly one element. If you declare more, the application throws a development exception when the view opens.

[[widget-size]]
=== Widget Size

By default, a widget takes one cell of the grid. The `colspan` and `rowspan` attributes make it span several columns and rows:

[source,xml,indent=0]
----
include::example$/vaadin-dashboard-ex1/src/main/resources/com/company/vaadindashboardex1/view/widgets/dashboard-widgets-view.xml[tags=widget-size]

A widget never takes more columns than the grid has. On a narrow screen, a wide widget shrinks to the number of columns available.

[[sections]]
== Sections

The `dashboardSection` element groups widgets under a common heading. Users can collapse a section and hide all its widgets at once:

[source,xml,indent=0]
----
include::example$/vaadin-dashboard-ex1/src/main/resources/com/company/vaadindashboardex1/view/sections/dashboard-sections-view.xml[tags=sections]
----

Like a widget, a section requires an `id`. A section can contain only `dashboardWidget` elements, and you cannot put a section inside another section. Widgets declared directly in the `dashboard` element and widgets inside sections can be mixed in any order.

[[responsive-grid]]
== Responsive Grid

The dashboard calculates the number of columns from its own width and from the column width limits. Columns never become narrower than the <<minimumColumnWidth,minimumColumnWidth>> value. When the dashboard becomes narrower, the number of columns is reduced instead. The <<maximumColumnCount,maximumColumnCount>> attribute sets the maximum number of columns on wide screens:

[source,xml,indent=0]
----
include::example$/vaadin-dashboard-ex1/src/main/resources/com/company/vaadindashboardex1/view/grid/dashboard-grid-view.xml[tags=grid]
----

The <<denseLayout,denseLayout>> attribute changes how the grid fills gaps. If it is `true`, smaller widgets move up into the empty space left by larger ones, and the declared order is not kept.

[[editable-mode]]
== Editable Mode

By default, users see the widgets exactly as they are declared. If you set the <<editable,editable>> attribute to `true`, users can move, resize, and remove widgets and change the order of sections:

[source,xml,indent=0]
----
include::example$/vaadin-dashboard-ex1/src/main/resources/com/company/vaadindashboardex1/view/editable/dashboard-editable-view.xml[tags=editable]
----

In this mode, each widget shows a drag handle, a resize handle, and a remove button. The same actions are available from the keyboard. A user selects a focused widget for editing and then moves or resizes it with the arrow keys.

You can switch the editable mode at runtime, for example with a *Customize* button:

[source,java,indent=0]
----
include::example$/vaadin-dashboard-ex1/src/main/java/com/company/vaadindashboardex1/view/editable/DashboardEditableView.java[tags=toggle]
----

The dashboard sends an event for every change made by the user. See <<handlers,Handlers>>.

[[theme-variants]]
== Theme Variants

Use the xref:flow-ui:vc/common-attributes.adoc#themeNames[themeNames] attribute to set a component theme.

[cols="1,4", options="header"]
|===
|Variant
|Description

|`shaded-background`
|Adds a shaded background to the dashboard, so that widgets stand out.

|`elevated-widgets`
|Shows widgets with a shadow.

|`flat-widgets`
|Shows widgets without borders and shadows.
|===

You can add custom CSS class names to the dashboard, its sections, and its widgets with the xref:flow-ui:vc/common-attributes.adoc#classNames[classNames] attribute.

[[attributes]]
== Attributes

The following attributes are specific to `dashboard`:

[cols="2,5,1", options="header"]
|===
|Name
|Description
|Default

|[[denseLayout]]`denseLayout`
|If `true`, smaller widgets move up to fill the gaps left by larger ones, and the declared order is not kept. See <<responsive-grid, Responsive Grid>>.
|`false`

|[[editable]]`editable`
|If `true`, users can move, resize, and remove widgets and change the order of sections. See <<editable-mode, Editable Mode>>.
|`false`

|[[gap]]`gap`
|The space between widgets, as a CSS length, for example `1em`.
|—

|[[maximumColumnCount]]`maximumColumnCount`
|The maximum number of columns, whatever the width of the dashboard is. If not set, the number of columns depends only on <<minimumColumnWidth,minimumColumnWidth>>.
|—

|[[maximumColumnWidth]]`maximumColumnWidth`
|The maximum width of a column, as a CSS length.
|—

|[[minimumColumnWidth]]`minimumColumnWidth`
|The minimum width of a column, as a CSS length. Columns never become narrower than this value. Instead, their number is reduced. See <<responsive-grid, Responsive Grid>>.
|—

|[[minimumRowHeight]]`minimumRowHeight`
|The minimum height of a row, as a CSS length. A row becomes higher if its content needs more space.
|—

|[[padding]]`padding`
|The space between the dashboard border and its widgets, as a CSS length.
|—

|[[rootHeadingLevel]]`rootHeadingLevel`
|The heading level for the titles of root-level items in the generated markup. It affects accessibility only.
|`2`
|===

|===
|Name
|Description

|[[DashboardItemMovedEvent]]`DashboardItemMovedEvent`
|Sent when a widget or a section is moved to a new position. The `getItem()` method returns the moved item, and `getSection()` returns its section.

|[[DashboardItemMoveModeChangedEvent]]`DashboardItemMoveModeChangedEvent`
